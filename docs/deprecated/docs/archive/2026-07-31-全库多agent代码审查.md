> **类别**：归档 · 审查  
> **日期**：2026-07-31  
> **范围**：全库静态审查（非仅近期 diff）

## 0. 一句话

多 agent 全库审查共确认 **约 20 条真实问题**（Critical 2 · High 6 · Medium 8 · Low 若干）。  
最高优先级：**自然腰带/花环饰品每 tick 损坏逻辑写坏**、**翅膀物品硬链客户端渲染器（DS 类加载风险）**、**斗篷激活未消耗融梦能量**、**天使方块物品无服务端守卫**。

本文件为审查归档，**不自动改代码**；开放修复项是否进待办由维护者并入 [`功能状态.md` §3](../功能状态.md#3-后续与开放项) 决定。

## 1. 审查范围与分工

| 路 | 覆盖 |
| :--- | :--- |
| A | `block/**` · `block/entity/**` · `world/**` · `worldgen/**` · `fluid/**` |
| B | `item/**` · `entity/**` · `menu/**` · `recipe/**` · `attachment/**` · `dreamnotes/**` · `config/**` |
| C | `registry/**` · `network/**` · `mixin/**` · `api/**` · `integration/**` · `command/**` · `util/**` · `data/**` · `PasterDreamMod.java` · **整份 PasterDreamAPI** · `thirdparty/**` |
| D | `client/**` · `smoketest/**` · 进度/San/笔记/进维/成就主路径 |

**不报**：命名/风格、纯可读性重构、无失败场景的 speculative 优化。  
**已降级/剔除的误报**：

| 误报 | 原因 |
| :--- | :--- |
| `countdownTeleport` / `grantSculkHeartMemory`「循环变量捕获导致多人只处理最后一个」 | enhanced-for 每轮迭代变量在 Java 中为 effectively final，lambda 捕获的是当轮引用，**不是**经典 `for (int i…)` 捕获 bug |
| `generateDungeon` 分帧 `schedule(i+1, () -> placeTemplate(..., layer, template))` 捕获 | 每轮的 `layer`/`template` 同样为 effectively final |
| 「PDEntityDeathEvents 循环捕获」 | 同上；且 `sp` 在 enhanced-for 内声明 |

## 2. 按严重度汇总（已抽查）

### Critical

#### C1. NatureBelt / Garland 饰品消费逻辑损坏

| 项 | 内容 |
| :--- | :--- |
| 文件 | `item/NatureBeltItem.java` · `item/GarlandItem.java`（`curioTick`） |
| 失败场景 | 随机条件触发时：`hurtAndBreak` 后因分号切断，**后续 `shrink(1)+setDamage(0)` 块与 if 无关地总是执行**（在 if 体内仍每触发一次就 shrink）；且 ctor 为 `stacksTo(1)` **无 durability(200)**，与原版不一致；无 `isClientSide` 守卫；`EquipmentSlot.MAINHAND` 与 curio 槽不匹配 |
| 证据 | ```java<br>if (Mth.nextDouble(...) < 0.004) {<br>  stack.hurtAndBreak(1, ..., MAINHAND); {  // 分号后裸块<br>    stack.shrink(1);<br>    stack.setDamageValue(0);<br>  }<br>}<br>``` 原版：`durability(200)` + `if (stack.hurt(1, rng, null)) { shrink; setDamage(0); }` |
| 修复 | 恢复原版 hurt 返回值判断；`.durability(200)`；server-only；用实体/`null` 正确 break 回调 |

#### C2. 翅膀物品硬 import 客户端 ArmorRenderer（专用服类加载风险）

| 项 | 内容 |
| :--- | :--- |
| 文件 | `item/armor/AngelWingItem.java` · `MachineWingItem.java` · `ForsakensWingItem.java` |
| 失败场景 | 物品类顶层 `import ...client.renderer.armor.*WingArmorRenderer`，类加载时连带加载依赖 `net.minecraft.client.*` 的渲染器 → **Dedicated Server 启动/注册阶段可能 NoClassDefFoundError** |
| 证据 | `createGeoRenderer` 内直接 `new AngelWingArmorRenderer()`；GeckoLib `GeoRenderProvider` 本可延迟，但 **静态 import 已使类依赖图不安全** |
| 修复 | 去掉 common 物品类对 client renderer 的硬引用；用独立 client 代理 / 反射 / `DistExecutor` / 仅字符串+client 注册表挂接；保证 DS 可加载物品类 |

### High

#### H1. 斗篷激活未消耗融梦能量（与原版/tooltip 不一致）

| 项 | 内容 |
| :--- | :--- |
| 文件 | `network/PDNetwork.java` → `executeCloakActivate` |
| 失败场景 | 佩戴回身/闪避斗篷按激活键：只要无 CD 即加 buff、播特效、上 7800 CD；**不检查、不消耗 10 点融梦能量**。注释写「已剥离至附属 mod」，但主模仍有 `MeltDreamEnergyAPI.consumeEnergy` / `PDAttachments.consumePlayerMeltDreamEnergy`，且 curios tooltip / VERIFY 仍写消耗 10 |
| 证据 | 原版 `CloakActivatePr0Procedure`：`if (consumePlayerMeltDreamEnergy(pl, 10)) { ... }`；现实现两处 `ifPresent` 内无 consume |
| 修复 | 在激活分支用 `MeltDreamEnergyAPI.consumeEnergy(player, 10)` 守卫；能量不足则不进入 CD/效果 |

#### H2. AngelBlockItem 放置无服务端守卫

| 项 | 内容 |
| :--- | :--- |
| 文件 | `item/AngelBlockItemItem.java` → `use` |
| 失败场景 | 客户端也会 `setBlock` + `shrink` → 幽灵方块、物品 desync、提前消耗 |
| 修复 | `if (!level.isClientSide && air) { setBlock; if (!creative) shrink; }`；正确返回 `InteractionResultHolder` |

#### H3. Qym（Qin）盔甲套装效果与原版偏离 + 副作用

| 项 | 内容 |
| :--- | :--- |
| 文件 | `item/QymArmorItem.java` |
| 失败场景 | 当前：4 件全套 → 再生/抗性/防火/跳跃，**无维度条件**；非满套时 **`removeEffect` 会剥掉其他来源同名效果**；每件护甲每 tick 都跑检查（×4） |
| 证据 | 原版 `QymArmorPr0Procedure` 为 3 件 + 维度相关逻辑（需对照确认意图） |
| 修复 | 若无意改版则还原原版条件；满套用短时 refresh 而非非满套全局 remove；单点事件/tick 聚合 |

#### H4. 暗影地牢生成 44 格清场会 discard 玩家

| 项 | 内容 |
| :--- | :--- |
| 文件 | `block/BrokenShadowDungeonProtalBlock.java` → `generateDungeon` |
| 失败场景 | `inflate(44/2)` 内 **所有实体** `discard()`，含玩家；多人靠近修复/生成时会被踢出世界 |
| 证据 | 与原版 `ShadowDungeonPortalPr2Procedure` 行为一致（ported hazard），多人仍危险 |
| 修复 | 排除 `Player`/`ServerPlayer`（及需保留的实体 tag）；缩小 AABB 或仅清怪物 |

#### H5. 暗影地牢传送门 use 路径 side 守卫不完整

| 项 | 内容 |
| :--- | :--- |
| 文件 | `BrokenShadowDungeonProtalBlock`（`useWithoutItem` / `startRepair` / `handleFixedInteraction`） |
| 失败场景 | 入口未统一 server-only；schedule / setBlock / 扣物品可能在客户端路径触发 → 双端不一致或 ClientLevel 入队 |
| 修复 | use 入口早期 `if (level.isClientSide) return SUCCESS;`；世界修改与 schedule 仅 server |

#### H6. Smoketest / VERIFY 大量 direct fixture，主路径假绿风险

| 项 | 内容 |
| :--- | :--- |
| 文件 | `smoketest/PDMainFlowVerifyHooks.java` 等（`DreamnotesLogic.onUse` 直调、`grantAdvancement` 预授） |
| 失败场景 | Sleep→发笔记→`DreamnotesItem.use`→成就→裂隙 `entityInside` 任一真实触发点坏掉，套件仍 pass |
| 修复 | 关键链改为真实 use/事件/等待 Scheduler；保留 fixture 仅用于不可达前置；补失败注入 |

### Low（摘录）

- 弹射物/翅膀 tick 使用 `Math.random()`，应统一 `RandomSource`。
- 部分 projectile `onTickEffect` 无粒子限流（高密度压力）。
- C2S handler 内冗余 `isClientSide` 检查（历史残留，非功能 bug）。
- 延迟任务（睡眠发笔记、翅膀关飞）边界上可再加强 `isAlive`/维度一致性。
- `PortalInfectionData` 字符串匹配感染方块、跨维 storage 边界需加固。
- 同维传送混用 legacy `teleportTo+connection.teleport` 与 `DimensionTransition`。
- Gallery/部分 VERIFY helper 特判 `accept(true)` 削弱边界覆盖。

## 4. 建议修复优先级

1. **立刻**：C1 饰品 shrink/耐久；C2 翅膀 client 隔离（先保证 `runServer`/DS 可起）。  
2. **玩法一致性**：H1 斗篷能量；H2 天使方块 side；H3 Qym 套装意图确认后修。  
3. **多人/地牢**：H4 清场排除玩家；H5 传送门 server-only。  
4. **工程**：H6 VERIFY 真路径；M1 菜单防御；M2 curios modifier id；M5 成就常量统一。  
5. **集成**：M6/M7/M8 KubeJS·JEI·注册触发。

**回归建议**：

```bash
JAVA_HOME=/usr/lib/jvm/java-21-openjdk sh gradlew :PasterDream:runServer --offline
# 以及
PASTERDREAM_VERIFY=1 PASTERDREAM_VERIFY_SUITES=quick,behavior \
  JAVA_HOME=/usr/lib/jvm/java-21-openjdk sh gradlew :PasterDream:runClient --offline
```

重点手测：NatureBelt/Garland 耐久消耗、翅膀 DS、斗篷能量 10、天使方块、Qym 满套/非满套、地牢生成旁站第二名玩家、饰品反复穿脱属性。
