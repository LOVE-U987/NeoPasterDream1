# 第一次贡献

> 本文档指导你完成从 Issue 到 PR 的完整贡献流程。

---

## 1. 找到适合的任务

### 查看 Issue

- 访问 [GitHub Issues](https://github.com/LOVE-U987/NeoPasterDream1/issues)
- 查找标记为 `good first issue` 或 `help wanted` 的 Issue
- 或者浏览仓库中未关闭的 Issue，了解当前待完成的功能

### 自定义任务

如果你有新功能想法:

1. 先创建 Issue 描述你的想法
2. 等待维护者确认
3. 获得批准后再开始开发

---

## 2. 创建分支

### 分支命名规范

使用 `类型/负责人/主题` 格式:

```bash
# 从 main 分支创建功能分支
git checkout main
git pull origin main
git checkout -b feature/your-username/my-feature

# 分支命名示例
feature/momonyako/dream-meter
fix/phantomdaze/loot-table
refactor/username/cleanup-api
docs/username/update-readme
```

### 分支类型

| 类型 | 用途 |
|------|------|
| `feature` | 新功能 |
| `fix` | Bug 修复 |
| `refactor` | 代码重构 |
| `docs` | 文档更新 |
| `test` | 测试相关 |

---

## 3. 开发流程

### 3.1 了解相关规范

在编码前,务必阅读:

- [代码规范](../开发指南/代码规范.md) — 命名、格式、编码规范
- [注册指南](../开发指南/注册指南.md) — 如何注册方块/物品/实体
- [资源规范](../开发指南/资源规范.md) — GeckoLib 目录结构

### 3.2 查阅对应文档

从 [文档入口](../README.md) 查找当前系统的规范。先用 [模块边界](../架构/模块边界.md) 确定代码归属；添加方块、实体或物品时,阅读对应 [教程](../README.md#教程)；涉及资源、注册或测试时,按 [AGENTS.md 的文档路由表](../../AGENTS.md) 阅读专项指南。

### 3.3 编写代码

1. **分析效果**: 查看原模组资源文件,理解游戏机制
2. **重新设计**: 基于 NeoForge 1.21.1 API 实现
3. **手写代码**: 使用 `DeferredRegister`、DataGen、GeckoLib

### 3.4 编译测试

先为新行为或 Bug 写出可复现的验收条件,再实现并验证。测试驱动流程和 VERIFY 套件选择见 [测试指南](../开发指南/测试指南.md)。

```bash
# 全量编译 (推荐)
.\gradlew compileJava

# 或仅编译变更涉及的模块
.\gradlew :PasterDream:compileJava
.\gradlew :PasterDreamSpells:compileJava

# 运行数据生成器 (如修改了数据文件)
.\gradlew runData

# 启动客户端测试
.\gradlew runClient
```

## 4. 提交代码

### 4.1 提交信息格式

```
类型(范围): 内容
```

**类型**:

| 类型 | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | Bug 修复 |
| `docs` | 文档更新 |
| `style` | 代码格式 (不影响运行) |
| `refactor` | 重构 |
| `test` | 增加测试 |
| `chore` | 构建/辅助工具变动 |

**范围** (可选):

| 范围 | 说明 |
|------|------|
| `api` | API 模块 |
| `block` | 方块相关 |
| `entity` | 实体相关 |
| `item` | 物品相关 |
| `model` | 模型相关 |
| `render` | 渲染相关 |
| `registry` | 注册系统 |
| `client` | 客户端代码 |
| `server` | 服务端代码 |

**示例**:

```bash
git commit -m "feat(api): add BiomeShading API for data-driven biome fog colors"
git commit -m "fix(item): make dyedream bud nugget drops scale with bud size"
git commit -m "docs(code & docs): update AGENTS.md with new conventions"
```

### 4.2 提交前检查

```bash
# 查看变更
git status
git diff

# 确保编译通过
.\gradlew compileJava

# 提交
git add .
git commit -m "your commit message"
```

## 5. 创建 Pull Request

### 5.1 推送分支

```bash
git push origin feature/your-username/my-feature
```

### 5.2 创建 PR

1. 访问 GitHub 仓库
2. 点击 `Compare & pull request`
3. 填写 PR 描述:

```markdown
## 变更内容
- 简要描述你做了什么

## 变更原因
- 为什么需要这个更改

## 测试情况
- [ ] 编译通过
- [ ] 客户端测试通过
- [ ] 无新增警告

## 关联 Issue
- Closes #123
```

### 5.3 PR 规范

- **标题**: 简洁描述更改内容
- **描述**: 详细说明变更内容、原因和影响
- **关联 Issue**: 如有相关 Issue,请关联
- **测试**: 确保编译通过,无新增警告

---

## 6. 代码审查

### 审查标准

- **代码质量**: 是否符合项目代码风格
- **架构一致性**: 是否符合项目架构设计
- **功能完整性**: 是否实现了预期功能
- **测试覆盖**: 是否有足够的测试
- **文档更新**: 是否更新了相关文档

### 常见修改意见

1. **命名问题**: 类/方法/变量命名不符合规范
2. **格式问题**: 缩进、空格、换行不规范
3. **架构问题**: 代码归属模块错误
4. **资源问题**: GeckoLib 目录结构错误
5. **注释问题**: 缺少必要注释

### 处理审查意见

```bash
# 根据审查意见修改代码
# ...

# 提交修改
git add .
git commit -m "fix: address review comments"
git push origin feature/your-username/my-feature
```

## 7. 合并

审查通过后,维护者会:

1. 使用 **Squash and Merge** 合并 PR
2. 确保 CI/CD 通过
3. 合并后删除功能分支

## 常见问题

### Q: 遇到编译错误怎么办?

1. 检查 Java 版本是否为 21
2. 运行 `.\gradlew clean` 清理构建缓存
3. 查看错误信息,定位问题文件
4. 参考 [问题排查](../开发指南/问题排查.md)

### Q: 不确定代码应该放在哪个模块?

参考 [模块边界](../架构/模块边界.md) 的归属决策表。

### Q: 如何运行测试?

```powershell
# 全量编译测试
.\gradlew compileJava

# 在 PowerShell 中运行 core VERIFY 套件
$env:PASTERDREAM_VERIFY = '1'
$env:PASTERDREAM_VERIFY_SUITES = 'core'
.\gradlew :PasterDream:runClient
```
