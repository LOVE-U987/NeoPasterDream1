# 染梦地物生成修复

日期：2026-11-08。

## 问题与内容归属

用户反馈染梦维度存在密集竖直云碎块、暖群系冰柱和方解石笋浮空。

方解石笋的实际注册名是 `grass_5`、`grass_6`，均使用 `CalciteSpikeBlock`。
`calcite_pillar` 是另一种大型方解石柱。排查初期曾误将两者混同；本次对大型柱的误改已全部撤回，
其 Java 注册和三个 JSON 与任务开始时一致，不作为本次修复内容。

## 方解石笋

原有问题有两层：

- 小笋从植被体系拆成普通 `Block` 后，没有实现支撑存活规则，默认可以在空气中存活。
- `grass_5/6` 的外层地表过滤仅检查散布起点；内层 `random_patch` 又做 XZ/Y 随机偏移，
  内层只检查空气，无法保证每个最终落点贴地，也无法限制其在洞穴内生成。

修复后的规则：

- 两种小笋从 `dyedream_vegetation` 移至独立的 `underground_decoration` 挂载，群系仍为染梦标签。
- 保留已有每区块 `count=2`、`rarity=10`，改为随机地下高度，补全 biome 过滤。
- 内层使用主模块 `CaveCalciteSpikeFeature`，逐点寻找有坚固石质支撑的空气格，并检查石质顶盖。
  向下搜索 16 格、顶盖搜索 32 格及允许的围岩材质均在配置中指定，不依赖固定海拔。
- 围岩允许方解石、石头、深板岩、染梦方块和 `minecraft:base_stone_overworld` 标签；
  第一处上方障碍为树叶、水或其他非围岩时拒绝。目标格有水或熔岩时不放置。
- 方块自身要求下方 UP 面坚固；拆除支撑后通过邻居更新移除。该规则也约束手动放置。
- 保留两变体模型、注册名、镐采集和掉落规则。地表水晶花园、石簇、大型柱不因名称相近而改动。

## 云团、冰柱与高度图

- `ground_feature_dyedream_2/4` 原纵向散布为 24/48，横向为 2/5；
  调整为纵向 2/3、横向 4/6，尝试数 48/96，保留原 rarity=4/12，并补全 biome 过滤。
- `ground_feature_dyedream_0/3` 从六类陆地群系的通用表面列表移出，单独挂载到寒冷冻原，
  不改变这两个特征的 ID 和次数。
- 自定义染梦地形直接覆盖 section 后，旧的父类高度图不能仅靠新增非空气方块更新。
  现在先清空并从实际方块重建 `WORLD_SURFACE_WG/OCEAN_FLOOR_WG`，再进行河流修改。
  `Unprimed heightmap` 日志本身会触发补算，不作为截图问题根因的唯一证据。

## 测试目录事故与保护

第一次客户端测试仅覆写 JavaExec 的 workingDir，但 ModDev 的 RunGameTask 会在执行时再次覆盖，
导致实际使用默认 `PasterDream/run`，自动测试重建了其中的 `test-audit` 测试存档。该失误已向用户说明；
不能宣称默认测试存档未受影响，也不将后续路径保护当作对已发生重建的恢复。

后续测试限定在 `.opencode/worldgen-client-01a1b910-v2`，同时设置 RunModel 与 RunGameTask 的 gameDirectory。
启动前核验规范绝对路径、实际 `--gameDir` 和不存在旧 `test-audit`，不符即中止；
启动后复查实际日志/存档位置，并比较默认测试存档指纹。

## 兼容与限制

修复影响重新启动后的新生成区域。不会主动扫描、清理或重生成旧区块；已有浮空笋仅在相关邻居更新时
按支撑规则移除。不能以编译、数据生成或仪式植物的 dyedream VERIFY 套件替代地物自然生成验证。
