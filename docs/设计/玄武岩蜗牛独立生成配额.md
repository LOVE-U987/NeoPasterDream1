# 玄武岩蜗牛独立生成配额

## 问题与目标

2026-11-09，用户要求玄武岩蜗牛改为独立计数，上限 16 只。
此前蜗牛与炽足兽均为 CREATURE；隔离实测中，连续 2400 tick 出现
CREATURE 计数 16、全局阈值 10、全部是炽足兽，蜗牛自然生成持续被阻断。

本次作为相对原模组的有意差异，将蜗牛划入专用类别，不改变实体 ID、AI、中性行为、
玄武岩三角洲生成群系、权重 20 或每组 2–4。

## 类别与上限

`META-INF/enumextensions.json` 声明 `PASTERDREAM_BASALT_SNAIL`，序列化名为
`pasterdream:basalt_snail`，类别基础配额为 16。保持 friendly=true、persistent=true、
despawnDistance=128，因此沿用友好生物的自然刷怪开关及 400 tick 调度频率。

使用 [NeoForge 1.21.1 枚举扩展机制](https://docs.neoforged.net/docs/1.21.1/advanced/extensibleenums/)，
由主模 `neoforge.mods.toml` 的 `enumExtensions` 字段接入。既有 biome modifier
根据实体实际类别注入新池，不再将蜗牛加入 CREATURE。

原版类别阈值仍会按可刷怪区块数缩放，实际自然阈值可能小于 16。
为避免整组生成或多玩家扩大类别阈值后超过 16，`BasaltSnailEntity.checkSpawnRules`
在每只 NATURAL 个体入场前检查专用配额；上限直接读取类别声明，不重复定义玩法值。

## 计数与兼容范围

- 硬上限按每个维度当前已加载的蜗牛计数，不采用局部 AABB，不扫描未加载区块。
- 与原版配额一致，排除 isPersistenceRequired 或 requiresCustomPersistence 的个体。
- 达到 16 只后拒绝下一只 NATURAL 生成；不删除已有个体。
- 刷怪蛋、命令等非自然生成途径不受本生成规则限制；其产生的非持久化蜗牛仍会占据后续自然配额。
- 实体注册名不变；既有已加载蜗牛随新的 EntityType 分类自动参与独立计数。
  加载已有超额个体时不会主动清除，只会停止继续自然补充。
- 不改变其他生物的类别或配额，也不新增 Mixin、事件订阅、网络包和附件。

## 验收

专项命令选择 `PASTERDREAM_VERIFY_SUITES=basalt-snail`。验收包括：

1. 真实加载独立分类与群系生成池，基础配额为 16，蜗牛不再位于 CREATURE 池。
2. 在炽足兽占满 CREATURE 配额时，15 只蜗牛允许自然生成，16 只拒绝下一只。
3. 满配额仍允许刷怪蛋的实体生成规则；持久化蜗牛不占自然配额。
4. 临时夹具清理后，观察 2400 个真实 tick 的正常自然生成；全维度快照不得超过 16。
5. CREATURE 饱和时仍观察到蜗牛自然产出，最后才调用调试刷怪入口验证逐只保护。
6. 全模块编译与全项目 DataGen，并检查本次文本格式与差异。

本轮运行证据和最终结果在完成后记录于下方，不以编译代替游戏内验收。

### 2026-11-09 运行结果

用户已确认游戏内可以正常自然生成。全模块 compileJava、全项目 runData 通过；
DataGen 没有引入额外的已跟踪生成资源差异。

最终专项报告：`.opencode/basalt-snail-cap-20261109-run2/pd_verify_report.json`，
23 PASS / 0 FAIL。六个全维度自然快照中，蜗牛数量为 4、10、13、10、6、8，
同时 CREATURE 始终为 19 / 10；确认两类配额独立。
真实自然观察为起始 0、峰值 13、结束 8；随后原版调试入口从 8 补充到 16，未越过上限。
15/16 边界、持久化过滤、刷怪蛋规则及夹具清理均通过。

两轮客户端均使用独立新建测试目录，不覆盖个人存档。用户运行中的旧游戏实例不会热替换枚举分类；
新构建需重新启动加载。本轮没有对个人旧存档进行加载/卸载区块的完整兼容回归。

首轮边界和配额隔离均通过：CREATURE 计数 30、阈值 10 时，蜗牛自然快照为 4、5 只；
调试入口从 0 补充后恰好停在 16。首轮报告为 22 PASS / 1 FAIL，失败项仅因
结束时数量回到 0 而忽略了中途已有自然产出。验收现改为记录观察期峰值，
不把个体在窗口结束时仍然存活作为生成成功的必要条件；原始失败报告保留。
