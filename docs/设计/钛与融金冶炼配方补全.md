# 钛与融金冶炼配方补全设计

> 关联资源：`data/pasterdream/recipe/titanium_ingot_smelting.json`、`moltengold_ingot_smelting.json`、`raw_titanium_smelting.json`、`titanium_ingot_blasting.json`、`moltengold_ingot_blasting.json`、`raw_titanium_blasting.json`
> 关联参考：原模组 `recipes/smelting_1.json`、`smelting_2.json`、`smelting_11.json`（只读基准）
> 记录日期：2026-11-02

## 1. 背景

原模组 14 条 smelting 配方中，本项目此前仅缺钛链条 3 条：

| 原模组配方 | 内容 | 本项目移植 |
|-----------|------|-----------|
| smelting_1 | `deepslate_titanium_ore` -> `raw_titanium` | 此前缺失 |
| smelting_2 | `raw_titanium` -> `titanium_ingot` | 此前缺失 |
| smelting_11 | `raw_moltengold` -> `moltengold_ingot` | 此前缺失 |

两侧矿石战利品表均直接掉落 raw 材料，但 raw 无冶炼出口，钛锭/融金锭只能靠 nugget 合成或宝箱随机获取，钛装备与融金装备进度链卡死。本次补全为**还原修复**（smelting 部分）叠加**有意差异**（blasting 部分）。

## 2. 配方内容

### 2.1 smelting（还原项）

参数与原模组逐项一致：`category: misc`、`experience: 1`、`cookingtime: 200`。

| 文件 | 输入 -> 输出 | 对应原模组 |
|------|-------------|-----------|
| `titanium_ingot_smelting.json` | `raw_titanium` -> `titanium_ingot` | smelting_2 |
| `moltengold_ingot_smelting.json` | `raw_moltengold` -> `moltengold_ingot` | smelting_11 |
| `raw_titanium_smelting.json` | `deepslate_titanium_ore` -> `raw_titanium` | smelting_1 |

`raw_titanium_smelting.json` 补齐后与融金侧既有移植（`raw_moltengold.json`，即原 smelting_10：`moltengold_ore` -> `raw_moltengold`）保持对称；丝之触碰玩家采集矿石本体后仍有入链途径。原模组中普通 `titanium_ore` 本就没有矿石熔炼配方，本移植如实保留该不对称。

### 2.2 blasting（有意差异项）

原模组不存在任何 blasting 配方；本移植按原版惯例为上述 3 条链路各补一条高炉配方：`category: misc`、`experience: 1`（与对应 smelting 一致，不改变收益）、`cookingtime: 100`（原版高炉半程时间）。

| 文件 | 输入 -> 输出 |
|------|-------------|
| `titanium_ingot_blasting.json` | `raw_titanium` -> `titanium_ingot` |
| `moltengold_ingot_blasting.json` | `raw_moltengold` -> `moltengold_ingot` |
| `raw_titanium_blasting.json` | `deepslate_titanium_ore` -> `raw_titanium` |

差异性质：体验增强，缩短冶炼时间，不改变产出与经验；用户决策记录于计划（2026-11-02）。

## 3. 格式约定

- 1.21.1 写法：`result` 用对象 `{"id": ..., "count": 1}`（对齐既有 `smelting_14.json` / `raw_moltengold.json`），不用原模组 1.20 字符串简写。
- smelting 采用 `smelting_14.json` 完整字段风格（含 `category`）。
- 不使用空数组 `conditions` / `functions`，规避 codec 静默失败。
- LF、UTF-8 无 BOM、2 空格缩进，与现有配方文件一致。

## 4. 验证

- 6 个文件 JSON 可解析；5 个注册名（`raw_titanium`、`titanium_ingot`、`raw_moltengold`、`moltengold_ingot`、`deepslate_titanium_ore`）均已在主模块注册（`PDItemsMaterials` / `PDItemsBlocks` / `PDBlocksVegetation`）。
- 与既有配方无冲突：`titanium_ingot_1/2`、`moltengold_ingot_1/2`、`raw_titanium_1` 均为 `crafting_shapeless`，type 与 ingredient 均不同。
- `gradlew compileJava` BUILD SUCCESSFUL（纯数据文件回归）。
- 可选实机：熔炉/高炉分别烧炼 raw_titanium、raw_moltengold、deepslate_titanium_ore，确认产物与耗时。

## 5. 风险

低风险：纯增量数据文件。若 recipe JSON schema 错误会在配方加载时退回不可用并留日志（与战利品表静默失败不同），异常时优先检查 `type` / `ingredient` / `result` 字段拼写。
