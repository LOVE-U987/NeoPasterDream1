# 存档兼容层（ID 别名 + 旧存档备份/更新提示）

> 实现版本：0.10.0-pre.3 起
> 关联计划：`.opencode/plans/id-compat-layer-and-save-upgrade.md`
> 关联文档：[API 边界](../参考/API边界.md)、[模块边界](../架构/模块边界.md)、[ID 迁移计划](ID迁移计划.md)

---

## 1. 目标与范围

统一处理模组迭代中「旧注册名 → 新注册名」的兼容问题，避免旧存档因改名/合并而丢失内容；
并在加载旧版本存档时自动备份、提示玩家确认更新。

**做**

- 静态注册表（方块/物品/实体/菜单/效果/粒子/音效/方块实体）的移植版内部旧 ID 别名。
- 旧存档检测 + 自动备份 + GUI/命令提示 + schema 标记。

**不做（本期）**

- 群系别名：旧群系 JSON 与新 JSON 双份并存，旧名仍注册 → 别名会被遮蔽（no-op）。
- 动态注册表（结构/地物）别名：动态注册表不参与 `RegistryManager` 的静态快照同步路径
  （`takeSnapshot` 只遍历 `BuiltInRegistries.REGISTRY`），别名生命周期与生效面不可控。
- 世界数据重写（chunk / NBT）。
- 原版 1.20.1 存档兼容。

---

## 2. 机制

底层复用 NeoForge 1.21.1 原生能力：

- `IRegistryExtension#addAlias(from, to)` / `resolve(id)`（`Registry` 接口已实现该扩展）。
- `DeferredRegister#addAlias(from, to)`：须在 `RegisterEvent` 之前调用。
- NeoForge 补丁已让 `MappedRegistry` 的 `get` / `getHolder` / `getId` 走 `resolve`，
  因此别名对真实反序列化路径生效。
- 静态注册表别名随 `RegistrySnapshot` 捕获，并在旧存档加载的 `RegistryManager.applySnapshot`
  中重放，实现旧存档数字 ID 重映射。

**注意**：`BaseMappedRegistry.addAlias` 对同一注册表键重复登记同一映射会抛
`IllegalStateException("Infinite alias loop detected")`，故 `IdAliasRegistry.applyStatic`
按具体 `from` 映射去重，多次调用只补应用新增别名（不会封锁整个注册表键）。

### 模块边界

| 模块 | 内容 |
|------|------|
| `PasterDreamAPI` `api/compat` | `IdAlias` / `IdAliasTable` / `IdAliasRegistry` / `IdCompatAPI`（通用框架，零具体 ID） |
| `PasterDream` `compat` | `PDIdAliases`（具体映射表）、`PDSaveSchema` / `PDSaveCompatData` / `PDSaveCompatHandler` / `SaveBackupHelper` |
| `PasterDream` `network` | `SaveUpgradePromptPayload`（S2C）、`SaveUpgradeConfirmPayload`（C2S） |
| `PasterDream` `client` | `SaveUpgradePromptScreen`、`PDSaveCompatClientEvents` |
| `PasterDream` `command` | `PDSaveCommand`（`/pasterdream save status\|backup\|upgrade`） |

## 3. 旧 ID 取证（Phase 0）

**方法**：对比初始全量移植提交 `5f465da1` 与当前 HEAD 的注册名字面量集合，
差集即「移植版自身早期曾注册、现已改名/合并」的旧 ID 候选。

```bash
# 逐条取证（限移植 Java 源码）
git log --all --oneline -S "<old_id>" -- */src/main/java
```

**判定口径**：

| 证据强度 | 含义 | 处理 |
|----------|------|------|
| 有效 | `git log -S` 命中移植 `*/src/main/java`（曾注册/引用） | 纳入别名表 |
| 无效 | 仅命中 `libs/` / manifest / docs（属原版模组名） | 剔除 |

> `pd_porting_manifest.json` 的 `renames` 是「原版模组 1.3fix → 移植版」映射，
> **不是**移植版早期旧 ID，不作为别名来源（如 `qym_armor_boots`、`uuz_doll_0`、
> `meltdream_chest_gui`、`breakwing` 从未出现在移植 Java 源码）。

## 4. 存档检测 / 备份 / 提示

### 4.1 版本标记

- `PDSaveSchema.CURRENT_ID_SCHEMA_VERSION`：当前 schema 版本（首次引入为 `1`）。
- `PDSaveCompatData`（`SavedData`，存主世界 DataStorage）：记录各模组 schema 版本、
  写入时的模组版本、最近升级时间。
- 新世界：`LevelEvent.CreateSpawnPosition`（仅新世界触发）写入当前版本。
- 旧存档：`ServerStartedEvent` 读取主世界标记；缺失或 `< CURRENT` 即判定为旧存档。

### 4.2 时序

| 事件 | 动作 |
|------|------|
| `LevelEvent.CreateSpawnPosition` | 新世界写入当前 schema 标记（避免误判） |
| `ServerStartedEvent` | 检测旧存档 → 自动备份到 `backups/` → 缓存结果（此时无玩家，不投递） |
| `PlayerLoggedInEvent` | 单机：S2C 弹窗；专用服务器：OP 系统消息（无 OP 在线仅日志） |
| 玩家确认 / `/pasterdream save upgrade` | 写入当前 schema 标记，停止提示 |

### 4.3 备份

- 目标目录：游戏目录 `backups/<世界名>_v<版本>_<yyyyMMdd_HHmmss>/`（与 `saves/` 同级，
  避免被原版世界选择界面识别为可进入世界）。
- **后台执行**：`ServerStartedEvent` 启动后台任务（`Util.backgroundExecutor()`），
  不阻塞服务器启动；完成后回主线程投递提示。进行中登录的玩家会在备份完成后收到提示。
  `/pasterdream save backup` 同样后台执行并回主线程回执。
- **并发守卫**：`SaveBackupHelper.tryAcquire()/release()`（`AtomicBoolean`）保证自动备份
  与手动备份同一时刻只有一个在跑；重复触发回复「已有备份任务在进行中」。
- **原子性**：先复制到 `<目标>.tmp`，成功后重命名；失败清理临时目录。
  `findBackup` 不将 `.tmp` 视为已完成备份，避免残缺备份被误判。
- **已有备份回填路径**：命中同版本备份时返回其路径并写入 `backupPath`，
  保证 GUI 显示路径、「打开备份目录」按钮可用、专用服务器通知含路径。
- 跳过 `session.lock`；同版本备份已存在则跳过；每 500 个条目输出一次进度日志。
- 一致性属 best-effort（服务器启动阶段执行）；失败降级为提示手动备份，可重跑命令。

### 4.4 命令

```
/pasterdream save status    # 查看存档/当前 schema 版本与备份路径
/pasterdream save backup    # 手动备份
/pasterdream save upgrade   # 写入当前 schema 标记（不重写世界数据）
```

权限：OP level 2（挂在 `save` 子节点）。

### 4.5 配置（`PasterDream-Common.toml`）

| 键 | 默认 | 说明 |
|----|------|------|
| `Save Compat.save compat enabled` | true | 旧存档提示/备份总开关 |
| `Save Compat.save compat auto backup` | true | 自动备份开关 |

## 5. 维护约定

1. 每次对**已发布内容**改名/合并：
   - 在 `PDIdAliases` 追加旧→新映射；
   - 递增 `PDSaveSchema.CURRENT_ID_SCHEMA_VERSION`；
   - 在本文件 3.2 表登记证据（commit hash）。
2. 禁止用 `pd_porting_manifest.json` 的 `renames` 反推移植版旧 ID。
3. 群系/动态注册表别名须先解决生效面问题（旧条目遮蔽、客户端同步）再纳入。

## 6. 验证

- `.\gradlew compileJava`
- `.\gradlew runClient`（`PASTERDREAM_VERIFY_SUITES=registry`）注册表 diff 通过
- `python tools/check_lang.py`
- `python tools/verify_resource_closure.py`（模型/纹理解析回退到 `src/generated/resources`，
  目标 `failure_count: 0`）
- 手测：
  - 新世界加载无提示、无备份；
  - 构造缺标记旧存档 → 触发自动备份 + 提示；确认后重启不再提示；
  - 备份失败降级；专用服务器命令可用；
  - 旧 ID（如 `pasterdream:wind_knight_spawnblock_0`）在 NBT/调色板中解析为新条目。

## 7. 里程碑 D（全量移植结束后）

- 由 `PDIdAliases`（代码常量表）反写 `pd_porting_manifest.json` 的 `renames`，统一单一事实源。
- 同步更新 `PDPortingVerifyTest` / `tools/verify_resource_closure.py` 基线说明，避免自证。
- 反写时归一为 UTF-8 + LF（现为 CRLF），会产生整文件 diff，需在提交说明中声明。
