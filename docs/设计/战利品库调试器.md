# 战利品库调试器设计

> 关联实现：`PasterDream/.../item/LootTableDebugCatalog.java`、`item/LootTableDebugItem.java`、`menu/LootTableDebugMenu.java`、`client/screen/LootTableDebugScreen.java`、`block/MeltdreamChestBlock.java`、`block/entity/MeltdreamChestBlockEntity.java`、`registry/PDMenus.java`、`registry/items/PDItemsFunctional.java`、`registry/creativetabs/PDCreativeTabsDebug.java`
> 关联资源：`assets/pasterdream/models/item/loot_table_debug_wand.json`、`assets/pasterdream/lang/zh_cn.json`、`assets/pasterdream/lang/en_us.json`

## 1. 背景与目标

战利品库调试器用于在开发与调试阶段快速验证任意宝箱战利品表：在界面中浏览本模组已加载的宝箱表，选择原版箱子或融梦水晶箱，再在目标位置生成带指定表的箱子。

设计目标：

- 一个物品完成“选表 + 选箱体类型 + 放置”全流程，选择随物品持久化。
- 界面只做选择，不直接生成方块；关闭界面后右键方块放置。
- 复用原版箱子与融梦水晶箱，不新增方块或容器。
- 普通融梦水晶箱路径保持零改动，调试覆盖仅在方块实体存在调试表时生效。

## 2. 物品与选择持久化

- 注册 ID：`loot_table_debug_wand`，显示名“战利品库调试器”。
- 属性：`stacksTo(1)`、`DataComponents.ENCHANTMENT_GLINT_OVERRIDE = true`（附魔光效）。
- 模型：`assets/pasterdream/models/item/loot_table_debug_wand.json`，`parent = item/handheld`、`layer0 = minecraft:item/stick`；不新增 PNG。
- 选择保存在 `DataComponents.CUSTOM_DATA`：
  - `pasterdream:loot_table_debug_table`：战利品表完整 ID 字符串；
  - `pasterdream:loot_table_debug_meltdream`：`true` 为融梦水晶箱，`false` 为原版箱子。
- 读取使用 `stack.getOrDefault(DataComponents.CUSTOM_DATA, CustomData.EMPTY).copyTag()`；写入使用 `CustomData.update(...)`，保留其他自定义键，不整体覆盖。
- Tooltip 显示当前表、箱体类型与操作提示；未选择时显示“当前未选择战利品表”。

## 3. 交互

| 操作 | 行为 |
|------|------|
| 右键空气 | 打开选择界面；目录为空时也打开空态界面 |
| 潜行右键方块 | 打开选择界面 |
| 普通右键方块 | 在点击面外侧生成当前选择的箱子 |
| 关闭界面 | 仅 `Esc` 关闭，无关闭按钮与键盘快捷键 |

放置规则：

- 目标位置校验：`level.mayInteract(player, target)`、`!level.isOutsideBuildHeight(target)`、`level.getBlockState(target).canBeReplaced()`；任一失败提示“此处无法放置箱子”并返回失败。
- 战利品表解析：`ResourceKey.create(Registries.LOOT_TABLE, id)` 后经 `server.reloadableRegistries().getLootTable(key)` 取表；表缺失或为 `LootTable.EMPTY` 时提示“战利品表不存在或为空”，不放置方块。
- 选择缺失、非法或不在当前目录时，回退到目录首项并写回物品，同时给出 actionbar 提示；目录为空时不写回。
- 所有成功/失败提示均通过 actionbar 输出，不打开聊天栏。

## 4. 目录扫描与分类

- 数据源：`server.reloadableRegistries().getKeys(Registries.LOOT_TABLE)`。
- 过滤：仅 `pasterdream` 命名空间，且路径以 `chests/` 或 `loots_` 开头。
- 每次打开界面重新扫描，数据包增删表后重新打开即可刷新。
- 分类顺序即枚举顺序，前缀均为完整路径前缀：

| 分类 | 匹配 | 翻译键 |
|------|------|--------|
| `RELIC`（遗迹） | `chests/loots_relic_` 或根级 `loots_relic_` | `gui.pasterdream.loot_table_debug.category.relic` |
| `DEEP_TREASURE`（深海秘宝） | `chests/loots_deep_treasure_` | `...category.deep_treasure` |
| `MELTDREAM_MAIN`（融梦主表） | 精确 `chests/loots_meltdream_chest_0` / `_1` | `...category.meltdream_main` |
| `MELTDREAM_EXTRA`（融梦附加） | `chests/loots_meltdream_chest_bonus_`、`_fallback_`、`_secondary_` | `...category.meltdream_extra` |
| `OTHER`（其他） | 其余进入列表的表 | `...category.other` |

- 排序：先按分类枚举序号，再按路径字典序。
- 左右按钮在两个非空分类之间跳转：从当前分类出发，按枚举顺序寻找上一个/下一个非空分类首项，边界循环；只有一个非空分类时回到该分类首项。
- 空目录：索引固定 0，界面显示空态，五个按钮禁用；服务端收到任何按钮 ID 均 no-op，禁止对 0 取模。
- 当前数据包下共 26 张表，分类计数为 10/4/2/10/0。

## 5. 选择界面

- 继承 `AbstractContainerScreen<LootTableDebugMenu>`，面板 280×168。
- 面板配色：原版灰 `#C6C6C6`，2px 黑色外框，左上 2px 白色高光，右下 `#555555` 2px 阴影。
- 文本使用默认 9px 字体，不绘制阴影；按钮使用原版 `Button`。
- 不新增 GUI PNG，不移植 HTML/CSS/JS。
- 所有坐标相对面板左上角，按钮在 `init()` 中按 `leftPos/topPos` 放置：

| 元素 | 坐标/尺寸 | 内容 |
|------|-----------|------|
| 标题 | 居中 y=9 | 选择战利品库 |
| 分类文字 | 居中 y=35，最大宽 182 | 分类：<分类名> |
| 分类左/右按钮 | x=9 / x=231，y=29，40×20 | 上一项 / 下一项 |
| 表路径 | 居中 y=64，最大宽 182 | 当前表路径，超长 `...` |
| 表左/右按钮 | x=9 / x=231，y=59，40×20 | 上一项 / 下一项 |
| 序号 | 居中 y=85 | 当前 / 总数 |
| 箱体类型 | 居中 y=100 | 箱体：原版箱子 / 融梦水晶箱 |
| 类型按钮 | x=50，y=114，180×20 | 切换箱体类型 |
| 底部提示 | 居中 y=144 | 关闭后右键方块放置 |

- 几何约束：左右按钮占 x=9..48 与 x=231..270，中间可用宽为 `231 - 49 = 182px`；分类文字与表路径统一按 182px 截断，保证不与按钮重叠。
- 表路径只显示 `ResourceLocation.getPath()`；悬停时显示完整 `pasterdream:...` ID。
- 路径截断使用 `font.width` 计算，保留 ASCII `...` 后缀。
- 空目录显示“未找到可用战利品表”，序号显示 `0 / 0`，五个按钮禁用。
- 按钮 ID：`UP = 0`、`DOWN = 1`、`TYPE = 2`、`CATEGORY_PREV = 3`、`CATEGORY_NEXT = 4`；点击统一经 `minecraft.gameMode.handleInventoryButtonClick(containerId, buttonId)` 发送。
- 每个按钮点击在服务端只调用一次 `commitSelection`：`UP/DOWN` 先移动一项，分类按钮先跳到相邻分类首项，类型按钮先翻转箱体类型，随后统一写回。
- `commitSelection` 是菜单内唯一写手持栈的入口，只写创建菜单时记录的 `InteractionHand`；写回前再次确认该手仍为 `LootTableDebugItem`，写入后调用 `player.inventoryMenu.broadcastChanges()` 与本菜单 `broadcastChanges()`。
- `stillValid` 只校验 `player.isAlive()` 与手持物品类型，不比较构造时捕获的物品栈：切换到非调试物品时菜单关闭，切换到另一把调试杖时继续对当前手持栈写入。
- 网络解码：表数量上限 4096，`count < 0 || count > 4096` 时抛 `DecoderException`，不按声明值做大分配；下标越界或空目录统一回落 0。

## 6. 箱子生成

### 6.1 原版箱子

1. 校验战利品表；缺失或 `LootTable.EMPTY` 直接失败，不放置方块。
2. 构造 `Blocks.CHEST` 状态：`ChestBlock.FACING = player.getDirection().getOpposite()`、`ChestBlock.TYPE = ChestType.SINGLE`。
3. `level.setBlockAndUpdate(target, state)`。
4. 方块实体不是 `RandomizableContainerBlockEntity` 时：`level.removeBlock(target, false)`、记录警告、提示放置失败、返回失败。
5. 否则 `container.setLootTable(key)`、`container.setChanged()`，提示已生成原版箱子。
6. `TYPE=SINGLE` 保证不并入相邻箱子，不走原版双箱合并逻辑。

### 6.2 融梦水晶箱

1. 同样先校验战利品表。
2. 构造 `PDBlocks.MELTDREAM_CHEST` 状态：`MeltdreamChestBlock.FACING = player.getDirection().getOpposite()`。
3. `level.setBlockAndUpdate(target, state)`。
4. 方块实体不是 `MeltdreamChestBlockEntity` 时：`removeBlock`、记录警告、提示失败。
5. 否则 `setDebugLootTable(id)`（内部 `setChanged()`），提示已生成融梦水晶箱。

## 7. 融梦水晶箱调试覆盖

- `MeltdreamChestBlockEntity` 新增 `@Nullable ResourceLocation debugLootTable`，NBT 键 `debugLootTable`，仅非空时写入字符串；`loadAdditional` 使用 `ResourceLocation.tryParse`，非法值置空并告警。
- `useWithoutItem` 只做分派：客户端返回、动画非 0 返回、方块实体校验通过后，`debugLootTable != null` 走 `openDebugChest`，否则走 `openNormalChest`。
- 普通路径 `openNormalChest` 原样保留：冷却检查、品质随机、`populateLoot`、音效、动画、冷却、成就、融梦能量。
- 调试路径 `openDebugChest` 顺序固定：品质随机（仅用于音效与动画）→ `populateDebugLoot` → 音效 → 设置动画 → `initOpening`；跳过冷却、成就与融梦能量，因此可无限重复开箱。
- `populateDebugLoot`：
  1. 先清空 9 格；
  2. 由 ID 取表，缺失或 `LootTable.EMPTY` 时告警、actionbar 提示并保持空库存，不回退普通逻辑；
  3. 使用现有 `rollTable` 过滤空栈，按顺序写入 slot 0 至 `min(size, 9) - 1`；
  4. 超过 9 件截断并告警；
  5. 不调用 `applyQualityExtras`、二级奖励、附加表或 `normalizeCrystal`，不把水晶移动到 slot 8；
  6. 重复开箱每次先清空再填充，不残留上一轮物品。
- `popNextItem` 的水晶特判改为 `slot == 8 && debugLootTable == null && stack.is(PDItemTags.MELTDREAM_CHEST_CRYSTAL)`：调试箱的水晶标签物品按普通物品弹出，不生成水晶实体。
- 普通融梦箱在 `debugLootTable == null` 时行为与改造前一致。

## 8. 创造栏归置

调试相关物品统一放入现有 `debug_tab`（“调试功能”），不新增创造栏、不重命名栏：

| 来源 | 物品 | 处理 |
|------|------|------|
| 纪念品栏 | `TABITEM_1`、`TABITEM_2` | 迁入 `debug_tab`，从纪念品栏删除重复输出 |
| 纪念品栏 | `LOOTSTABLE_CREATE_0` 至 `LOOTSTABLE_CREATE_9` | 同上 |
| 武器栏 | `EXCAVATOR` | 迁入 `debug_tab`，从武器栏删除重复输出 |
| 新增 | `LOOT_TABLE_DEBUG_WAND` | 只加入 `debug_tab` |

- 调试栏内在 `PASTER_BLOCK_RESET_TOOL` 之后依次新增“战利品表调试工具”“调试用挖掘工具”“原版调试栏/拓展栏图标占位物品”三组，不重排其他条目。
- 已在调试栏的 `CLAYPAN_1`、`GUARD_BLOCK`、`RESTRAINMOVE_BLOCK`、`LOST_SWORD_BLOCK`、`PASTER_BLOCK_RESET_TOOL`、`AARONCOS_ARENA_CREATE`、`TEST_CURIO` 不移动。
- 功能栏的 `CLAYPAN_0`、`CLAYPAN_2` 属装饰/功能方块，不迁移。
- 迁移只改 `output.accept` 归属，不删除注册、物品定义或战利品表占位用途。

## 9. 有意差异

1. 不实现关闭按钮与键盘快捷键：界面只保留 `Esc` 关闭，方向键与 `T` 键快捷键不实现。
2. 调试物品统一放入 `debug_tab`：`TABITEM_1/2`、`LOOTSTABLE_CREATE_0..9`、`EXCAVATOR` 与新增调试器不再散落在纪念品栏或武器栏。
3. 所有已发布注册 ID 保持不变：`loot_table_debug_wand`、`lootstable_create_0..9`、`tabitem_1/2`、`excavator` 均未改名，不触发 ID 迁移或存档兼容改动。
4. 调试箱的水晶标签物品按普通物品弹出，不生成水晶实体，且调试箱不授予成就、不增加融梦能量、不受冷却限制。

## 10. 验证要点

- `.\gradlew :PasterDream:compileJava` 退出码 0。
- `.\gradlew runData` 退出码 0，且本功能不新增/改写 DataGen 产出的 JSON。
- `python tools/check_lang.py`：29 个新键中英齐全、无空值。
- `python tools/verify_resource_closure.py`：新增模型可解析，`minecraft:item/stick` 纹理存在。
- 创造栏：迁移物品在 `debug_tab` 各出现一次，纪念品栏与武器栏不再出现，`debug_tab` 显示名仍为“调试功能”。
- 界面：GUI 缩放 1/2/3/4 下文字与按钮不重叠；分类文字与路径不超过 182px；类型按钮左右边距各 50。
- 交互：上下按钮逐项切换、左右按钮跳分类首项并循环、类型按钮切换箱体；连续点击后 `CUSTOM_DATA`、tooltip 与界面显示一致。
- 放置：原版箱 `TYPE=SINGLE` 不与相邻箱合并；不可替换/受保护位置有提示；融梦箱 NBT 含正确的 `debugLootTable`。
- 调试覆盖：只来自选中表、最多 9 格、无品质附加/二级奖励/纪念品/水晶归位；重复开箱无残留；跳过冷却、成就与融梦能量。
- 边界：空目录界面正常打开且五按钮无动作；表缺失时保持空库存并有提示；旧存档无 `debugLootTable` 字段时可正常读取。
- 回归：普通融梦箱、`lootstable_create_0~9`、`EXCAVATOR`、`TABITEM_1/2`、`CLAYPAN_0/1/2` 行为不变；无槽位菜单不产生物品复制。
