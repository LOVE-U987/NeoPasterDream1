# 丛林孢子掉落时运设计

> 关联资源：`data/pasterdream/loot_table/blocks/jungle_spore_plant.json`
> 关联实现：`PasterDream/src/main/java/com/pasterdream/pasterdreammod/block/JungleSporePlantBlock.java`（生长机制，与本设计无直接关联）
> 记录日期：2026-10-08

## 1. 背景

`pasterdream:jungle_spore_plant`（丛林孢子植株）普通掉落为 `pasterdream:jungle_spore`。原模组战利品表对本方块无时运加成，本项目为其新增「受时运影响」机制，属相对原模组的**有意改进**（非还原项）。

## 2. 机制

- 基础掉落：`jungle_spore` × 1（非精准采集）。
- 时运加成：采用原版 `minecraft:apply_bonus` + `minecraft:binomial_with_bonus_count`。
- 参数：`extra = 0`、`probability = 0.15`。
- 语义：原版 `ApplyBonusCount.BinomialWithBonusCount` 令 `n = 时运等级 + extra`，逐次独立判定 `random.nextFloat() < probability`，命中则 +1。故本配置为**每级独立一次 15% 概率 +1**。

## 3. 期望与边界

| 时运等级 | 独立判定次数 | 最多额外 | 最大总量 | 期望总量 |
|:---:|:---:|:---:|:---:|:---:|
| 0 | 0 | 0 | 1 | 1.00 |
| I | 1 | +1 | 2 | 1.15 |
| II | 2 | +2 | 3 | 1.30 |
| III | 3 | +3 | 4 | 1.45 |

## 4. 数据表结构

`data/pasterdream/loot_table/blocks/jungle_spore_plant.json` 含两条互斥池：

1. 池 1：非精准采集 → `jungle_spore`（`set_count` 后接 `apply_bonus`）。
2. 池 2：精准采集 → `jungle_spore_plant` 本体（不接时运）。

> `apply_bonus` 必须置于 `set_count` 之后，否则加成会被 `set_count` 覆盖。

双附魔（精准采集 + 时运）时走池 2，掉本体且不吃时运，符合原版惯例。

## 5. 验证

- JSON 可解析；`python tools/verify_resource_closure.py` 确认全库 JSON 可解析且无 BOM（另有 `libs/` 原模组 shadowshelf 历史对等缺口，与本设计无关）。
- 文件 LF、UTF-8 无 BOM。
- 可选实机：分别以时运 0/I/II/III 工具挖掘，确认掉落随等级提升。

## 6. 风险

1.21.1 战利品表若 schema 错误会整体退回 `LootTable.EMPTY`（方块无掉落且无报错），故字段名须与 `ApplyBonusCount` codec 严格一致（`formula` / `parameters.extra` / `parameters.probability` / `enchantment`）。
