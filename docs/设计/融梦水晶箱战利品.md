# 融梦水晶箱战利品设计

> 关联实现：`PasterDream/.../block/MeltdreamChestBlock.java`、`block/entity/MeltdreamChestBlockEntity.java`、`config/MeltdreamChestLootConfig.java`、`config/MeltdreamChestLootConfigMigration.java`、`api/doll/DollAPI.java`、`registry/PDItemTags.java`、`registry/PDDollLootRegistrations.java`
> 关联资源：`data/pasterdream/loot_table/chests/*.json`、`data/pasterdream/tags/item/music_discs.json`、`data/pasterdream/tags/item/meltdream_chest_crystal.json`
> 记录日期：2026-09-25

## 1. 背景

原版融梦水晶箱的战利品完全由战利品表 `loots_meltdream_chest_0`（染梦）/`loots_meltdream_chest_1`（风旅/灯影）决定，包含 4 条独立池：材料 / 宝石 / **饰品** / 装备。移植版曾弃用该表、改为「3 品质手写配置池」，导致原版饰品池的 11 件饰品缺失（仅剩万象神戒与啵啵鸡的华丽飞羽可开出）。

本设计将默认掉落改回原版战利品表，把三品质配置池降级为可选覆盖，并将全部物品集合解耦为数据驱动（战利品表 / 物品标签 / DollAPI），不再在 Java 中硬编码具体物品。

## 2. 数据驱动的物品集合

| 集合 | 来源 | 说明 |
|------|------|------|
| 维度主掉落 | `loots_meltdream_chest_0/_1.json` | 原版 4 池，数据包可覆盖 |
| 品质附加（水晶/纪念品） | `loots_meltdream_chest_bonus_common/rare/legendary.json` | 水晶必出（传说）、纪念品约 10% |
| 兜底（非梦境/主表缺失/自定义池全无效） | `loots_meltdream_chest_fallback_common/rare/legendary.json` | 各品质基础件数与旧池一致 |
| 唱片 | 物品标签 `pasterdream:music_discs`（13 张） | 代码按标签取样，优先未拥有 |
| 玩偶/雕像 | `DollAPI.getLootItems()` | 旧 5 玩偶经 `PDDollLootRegistrations` 登记，动态玩偶由 `DollBuilder` 自动登记 |
| 水晶识别 | 物品标签 `pasterdream:meltdream_chest_crystal` | `popNextItem` 据此生成水晶实体 |

> 空条目约定：战利品表内用 `pasterdream:tabitem_1` + `set_count {min:0,max:0}`（仓库既有惯例），代码统一 `isEmpty()` 过滤，不使用字面 `minecraft:empty`。

## 3. 三层解析

开箱时先 `selectQuality(random)` 决定品质（仅用于动画/音效与附加档位），随后按以下优先级填充：

1. **自定义开关开启**（`meltdream chest custom loot enabled = true`）且玩家池非空
   - 逐条容错解析玩家池（非法条目跳过，数量/权重钳制）
   - 池空或全无效 → 记警告，回退兜底表
2. **梦境维度主表有效**
   - 染梦 → `loots_meltdream_chest_0`；风旅/灯影 → `loots_meltdream_chest_1`
   - 表缺失/`LootTable.EMPTY` → 记警告，回退兜底表
3. **非梦境维度 / 主表回退** → 兜底表 `loots_meltdream_chest_fallback_<quality>`

三路均在基础填充后统一执行 `applyQualityExtras`。

## 4. 基础填充与附加

### 4.1 基础填充

- 配置池路径 `fillBaseFromPool`：普通 8 件（slot 0..7）、稀有 7 件（slot 1..7，slot 0 留给唱片）、传说 8 件（slot 0..7）
- 表路径 `fillFromLootTable`：以 `LootContextParamSets.CHEST` + `ORIGIN` + `withLuck` + `THIS_ENTITY` 取 `getRandomItems`，过滤空栈，顺序写入 `slot 0..n-1`（`n≤8`，超 8 截断并警告），其余清空
- 兜底表 `rolls` 与配置池件数一致：common 8 / rare 7 / legendary 8

### 4.2 品质附加 `applyQualityExtras`

| 品质 | 算法 |
|------|------|
| 1 普通 | 仅附加表 |
| 2 稀有 | slot 0 放唱片（slot 0 空则直放；否则基础整体右移 1 位）；50% 玩偶放首个空槽 |
| 3 传说 | `baseCount≥2` 时随机替换一个基础槽为玩偶（保留至少一件），否则玩偶放空槽 |
| 2/3 | 附加表：水晶标签项 → slot 8；纪念品 → 首个空槽（约 10%） |
| 收尾 | `normalizeCrystal`：将首个水晶标签项与 slot 8 交换（不覆盖丢件） |

边界：`firstEmptySlot < 0` 跳过；`rollFromPool`/`rollDisc`/`rollDoll` 对空集合返回空栈；`_1`（n=1）传说档不替换唯一基础件。

## 5. 维度映射与有意差异

| 维度 | 表 |
|------|----|
| 染梦世界 `dyedream_world` | `loots_meltdream_chest_0` |
| 风之旅途 `wind_journey_world` | `loots_meltdream_chest_1` |
| 灯影世界 `lamp_shadow_world` | `loots_meltdream_chest_1` |
| 其它 | `loots_meltdream_chest_fallback_<quality>` |

与 PasterDream 原版的差异（有意）：

- 原版品质（Pr1/Pr2/Pr3）同时决定动画/音效与部分维度的取表分支；本实现统一按维度取表，品质不再影响取表。
- 非梦境维度原版不挂表（无掉落），本实现回退兜底表。此为兼容旧移植行为的保守选择，**不构成防刷**（稀有档兜底池亦含 11 件饰品）。
- 默认路径附加唱片/玩偶/水晶/纪念品为移植版扩展，原版战利品表不含。
- 配置池路径统一应用附加表，也获得约 10% 纪念品（原配置池路径无）。
- 稀有档玩偶由旧版「随机覆盖 slot1..8、可能吞一件基础物」改为「追加到首个空槽」（不吞件）。

## 6. 配置与迁移

- 三个品质物品池默认值为空列表；自定义开关保留，开启后玩家池逐条容错，留空/全无效回退兜底表。
- 一次性迁移 `MeltdreamChestLootConfigMigration`：挂 `ModConfigEvent.Loading`（1.21.1 起 `EventBusSubscriber.bus()` 被忽略，事件总线按 `IModBusEvent` 自动判定）。仅当配置值逐条等于旧内置默认时清空，玩家自定义保留；以 TomlWriter 直写落盘（不调用 `ILoadedConfig.save()`，规避 `Reloading` 副作用）。

## 7. 验证要点

- `:PasterDream:compileJava` 通过
- 战利品表/标签 JSON 可解析：`music_discs` 13 项、`meltdream_chest_crystal` 1 项、`_0` 含 11 件饰品
- bonus/fallback 各表键 `getLootTable != LootTable.EMPTY`
- 三路件数与布局等价：稀有 slot 0 唱片、slot 8 可放玩偶；传说 slot 8 水晶；`_1`（n=1）传说档基础件不被替换
- `DollAPI.getLootItems()` 含旧 5 + 4 自定义玩偶；空集合不崩溃
- 数据包清空 bonus/fallback/标签时容忍并告警
- 迁移对旧默认清空、对自定义保留
