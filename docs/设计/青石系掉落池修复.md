# 青石系方块掉落池修复

- 日期：2026-11-03
- 类型：bug 修复（数据文件）
- 范围：`PasterDream/src/main/resources/data/pasterdream/loot_table/blocks/`

## 1. 问题

`cyan_stone`、`cyan_stone_bricks`、`cyan_stone_pillar`、`cyan_stone_button`、
`cyan_stone_pressure_plate` 五个方块的战利品表均为 `"pools": []`，而
`PDBlocksDyedreamPhase2` 将它们注册为普通 `Block` 等原生类（无 `getDrops` 兜底），
导致生存模式无法获得上述方块，风维地表采集链与相关建筑配方断裂。

原模组的 `CyanStone*Block` 均覆写 `getDrops`：vanilla 掉落为空时兜底返回自身
（原模组对青石系未提供任何 `loot_tables` JSON，掉落完全依赖 Java 兜底）。

## 2. 修复

按项目「普通 Block + 手写战利品表」既有模式（同族 `cyan_moss_stone` 等一致），
为 5 个方块补齐标准 1.21.1 自掉落表：单 pool、`set_count` 1-1 + `explosion_decay`、
`random_sequence` 为 `pasterdream:blocks/<方块名>`；不修改任何 Java。

同时清理 6 个孤儿/错名战利品表残留（`cyan_stone_slab`/`stairs`/`wall`/`smooth`
对应的方块从未注册；`cyan_stone_chiseled_bricks`/`cyan_stone_mossy_bricks` 为早期
错名文件，正确表 `chiseled_cyan_stone_bricks`/`mossy_cyan_stone_bricks` 已存在），
并同步移除 `PasterDream/tag_audit.json` 中对应的 6 条陈旧清单键。

## 3. 有意差异

原模组 `getDrops` 兜底使青石系**徒手挖掘（无镐）也掉落自身**；战利品表方案下
徒手无掉落、镐正常掉落（`cyan_stone` 等带 `requiresCorrectToolForDrops()`）。
与同族 `cyan_moss_stone` 已有行为一致，视为有意差异，不复刻徒手掉落。

## 4. 验证

- 5 张新表 JSON 可解析、pools 非空、`random_sequence` 与文件名一致；全目录无
  复数 `loot_tables` 目录、无 1.20 旧格式 `match_tool` predicate 残留。
- 6 个孤儿文件全项目零引用；`tag_audit.json` 无陈旧键残留。
- 改动文件均为 LF / UTF-8 无 BOM。
- `.\gradlew compileJava` 通过（纯资源改动）。

## 5. 范围外遗留（2026-11-03 记录）

审计中发现的待处理项（未在本次修复范围内）：

- 4 个空池战利品表：`dream_spawner_0.json`、`small_stone_spirit_block.json`、
  `starcall_block.json`、`starcall_crack.json`（后两者为限时自毁方块，是否应掉落待判定）。
- 部分既有战利品表文件（如 `cyan_moss_stone.json`、`cyan_stone_brick_slab/stairs/wall.json`）
  为 CRLF 换行，与 LF 规范不一致（不影响加载，属历史格式残留）。
