## 1. 定位

原模组中 `memento_item_08` 仅为「使用后幸运 +10 持续 3 分钟」的消耗品。本项目将其重做为
「夜空绘星」玩法：玩家在染梦维度的夜晚，用星空枕在星空上点亮星体并连成线，从星空获得
祝福与物品。

本次为**玩法级重构**：由原来的纯客户端视觉功能，改为服务端权威、全服同步的持久化玩法。

---

## 2. 重构前现状

| 项 | 现状 |
|----|------|
| 交互 | 右键在视线方向创建星体，左键移除对准星体 |
| 数据 | 仅存客户端内存（`PlayerSkyLinkData`），不持久化、不跨存档 |
| 星体 | 玩家随意创建，无对准校验 |
| 同步 | 无网络同步 |
| 结算 | 无收益，纯视觉 |
| 生效范围 | 任意维度夜晚 |

## 3. 重做目标

| 维度 | 结论 |
|------|------|
| 核心玩法 | 玩家右键星体，链式依次连线，获得星空祝福/物品 |
| 星体生成 | 世界种子确定性随机，并同步生成若干星座簇；全服一致 |
| 生效范围 | 仅染梦维度（`dyedream_world`）夜晚；数据不跨维度、不跨存档 |
| 连线数据 | 全服共享可见；每人各自一套链；不能操作他人链；同一星可被多人连 |
| 结算 | 预置星座匹配 = 大奖；自由连线 = 每人每日限次的小额奖励 |
| 视觉 | 本人连线高亮、他人连线暗色，颜色区分 |
| 保留 | 羽星占卜图录与星体的联动；织星者成就（完成条件改为完成首次连线） |
| 星数上限 | 沿用现有配置项 `SKYLINK_MAX_STARS` |
| 奖励内容 | 暂留可插拔占位，后续补充 |

## 4. 玩法规则

### 4.1 生效条件

- 维度：仅染梦维度。
- 时间：仅夜晚（沿用现有夜晚因子判定）。
- 持物：主手或副手持有星空枕。

不满足时给出对应提示（如「仅在染梦的夜晚可用」）。

### 4.2 星体生成

- 星体由**世界种子**确定性随机生成，同一存档所有玩家看到的星空完全一致。
- 生成星体时同步生成若干**星座簇**（每个星座簇包含一组节点与其规范连线集）。
- 星体总数沿用配置项 `SKYLINK_MAX_STARS`。
- 星体布局不随玩家变化、不随会话变化；跨存档由种子决定。

### 4.3 连线操作

- **右键星体**：将该星追加到本人当前链尾，与上一颗星连成一条边。
- 链式规则：新星与链尾相同则忽略；否则追加并生成一条边。
- **左键**：撤回本人最后一条连线（不退还已发奖励、不返还当日领奖次数，防刷）。
- 不同玩家可连接同一颗星；玩家只能操作自己的链。

### 4.4 结算与奖励

- **星座大奖**：当玩家已连出的边集合完整包含某个预置星座的规范边集时，触发大奖。
  同一玩家同一星座每日只结算一次。
- **自由连线小额**：其余连线给予小额奖励，受「每人每日限次」控制。
- 奖励具体内容（祝福效果 / 物品清单）待补充，实现上留可插拔钩子。

### 4.5 每日重置

- 连线保留至次日，随后删除（跨日重置）。
- 重置范围：所有玩家的链、当日自由连线领奖次数、当日已完成星座记录。
- 星体布局本身不重置（由种子决定）。
- 重置在维度 tick、玩家登录、进入染梦维度三处补检，避免无玩家 tick 时漏掉日界。

### 4.6 多人规则

- 全服共享可见：所有玩家的连线对所有玩家可见。
- 数据归属：连线按玩家独立存储，玩家不能操作他人连线。
- 同一星体可被不同玩家分别连线。

### 4.7 视觉表现

- 星体与连线沿用现有天空盒渲染架构（`AFTER_SKY` 阶段、天空球坐标约定）。
- 本人连线：高亮暖色；他人连线：暗色冷色，与本人明显区分。
- 仅染梦维度渲染；夜晚淡入、白天不可见。

## 5. 与现有系统关系

| 系统 | 处理 |
|------|------|
| 羽星占卜图录（`memento_item_03`） | 保留联动。占卜的「对准天体」判定改为读取同步后的星体数据；非染梦维度星源为空，自动跳过连线星分支 |
| 织星者成就（`achievement_skylink`） | 保留成就，完成条件由「创建第一颗星体」改为「完成首次连线」，由服务端授予 |
| 宝箱获取 | 保留（染梦遗迹宝箱 / 融梦水晶箱） |
| 配置 | 沿用 `SKYLINK_MAX_STARS`（语义改为染梦夜空星体总数）；新增自由连线每日领奖限次配置 |
| 观星者成就（`achievement_stargaze`） | 不受影响 |

## 7. 设计原则遵循

- 服务端权威：连线与奖励结算在服务端进行，客户端仅请求与渲染。
- 数据驱动：星体布局由种子确定性生成，不硬编码具体坐标。
- 模块归属：玩法逻辑与客户端渲染均落主模块，不误上收 API。
- 不修改 `libs/`、不复制 MCreator 代码。
