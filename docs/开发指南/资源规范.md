# 资源规范

> 本文档定义 PasterDream 项目的资源目录结构,包括 GeckoLib 模型、动画、纹理的放置规则。

---

## GeckoLib 目录结构

GeckoLib 的 `DefaultedGeoModel` 系列会根据 `subtype()` 自动决定资源路径的二级子目录:

| 模型类型 | 模型文件 (`geo/`) | 动画文件 (`animations/`) | 纹理文件 (`textures/`) |
|---------|------------------|------------------------|----------------------|
| `DefaultedEntityGeoModel` | `geo/entity/<name>.geo.json` | `animations/entity/<name>.animation.json` | `textures/entity/<name>.png` |
| `DefaultedBlockGeoModel` | `geo/block/<name>.geo.json` | `animations/block/<name>.animation.json` | `textures/block/<name>.png` |
| `DefaultedItemGeoModel` | `geo/item/<name>.geo.json` | `animations/item/<name>.animation.json` | `textures/item/<name>.png` |

> **口诀**: entity → entity/、block → block/、item → item/,别一股脑全塞 entity/ 里!

---

## 特殊情况处理

### BlockItem/DualRenderer (方块 & 物品共用资源)

方块渲染器走 `block/`,物品渲染器如果也使用 `DefaultedBlockGeoModel`,则物品的动画/模型也走 `block/` 路径。

```java
// 方块渲染器
public class MyBlockRenderer extends GeoBlockRenderer<MyBlockEntity> {
    public MyBlockRenderer(EntityRendererProvider.Context context) {
        super(context, new DefaultedBlockGeoModel<>(ResourceLocation.fromNamespaceAndPath(MOD_ID, "my_block")));
    }
}

// 物品渲染器 (共用方块资源)
public class MyItemRenderer extends GeoItemRenderer<MyItem> {
    public MyItemRenderer() {
        super(new DefaultedItemGeoModel<>(ResourceLocation.fromNamespaceAndPath(MOD_ID, "my_block")));
    }
}
```

### 自定义 GeoModel 子类

路径完全由代码中硬编码的 `ResourceLocation` 决定,与上述约定无关。

```java
// 自定义 GeoModel
public class MyItemModel extends GeoModel<MyItem> {
    @Override
    protected ResourceLocation getModelResource(MyItem animatable) {
        return ResourceLocation.fromNamespaceAndPath(MOD_ID, "geo/item/my_item.geo.json");
    }
    
    @Override
    protected ResourceLocation getTextureResource(MyItem animatable) {
        return ResourceLocation.fromNamespaceAndPath(MOD_ID, "textures/item/my_item.png");
    }
    
    @Override
    protected ResourceLocation getAnimationResource(MyItem animatable) {
        return ResourceLocation.fromNamespaceAndPath(MOD_ID, "animations/item/my_item.animation.json");
    }
}
```

**重要**: 修改代码中的路径字符串时,必须同时确认文件实际存在。

## 常见错误

### 错误 1: 方块动画放到 entity/ 目录

```java
// 错误 ❌
ResourceLocation model = ResourceLocation.fromNamespaceAndPath(MOD_ID, "geo/entity/dream_cauldron");

// 正确 ✅
ResourceLocation model = ResourceLocation.fromNamespaceAndPath(MOD_ID, "geo/block/dream_cauldron");
```

**后果**: 方块动画不播放,无报错。

### 错误 2: 实体动画放到 animations/ 根目录

```java
// 错误 ❌
animations/shadow_golem.animation.json

// 正确 ✅
animations/entity/shadow_golem.animation.json
```

**后果**: 实体动画不播放,无报错。

### 错误 3: 自定义 GeoModel 改路径后不检查文件是否存在

```java
// 错误 ❌
@Override
protected ResourceLocation getModelResource(MyItem animatable) {
    return ResourceLocation.fromNamespaceAndPath(MOD_ID, "geo/item/new_name.geo.json");
    // 但文件实际还是 old_name.geo.json
}

// 正确 ✅
// 1. 修改代码中的路径
@Override
protected ResourceLocation getModelResource(MyItem animatable) {
    return ResourceLocation.fromNamespaceAndPath(MOD_ID, "geo/item/new_name.geo.json");
}

// 2. 重命名文件
// geo/item/old_name.geo.json → geo/item/new_name.geo.json
```

**后果**: 运行时 FileNotFoundException。

## 操作检查清单

每次从原模组复制动画/模型/纹理文件后,必须核对:

- [ ] 文件放对子目录了? (entity/entity? block/block? item/item?)
- [ ] 对应的 Renderer 用了哪种 `DefaultedGeoModel`?
- [ ] 自定义 `GeoModel` 的硬编码路径与文件实际位置一致?
- [ ] 对于 `animations` 根目录、`animations/entity/`、`animations/block/`,每个目录里没有不相关的文件?

## 语言文件

### 格式

```json
{
    "block.pasterdream.my_block": "My Block",
    "item.pasterdream.my_item": "My Item",
    "entity.pasterdream.my_entity": "My Entity",
    "pasterdream.enchantment.my_enchantment": "My Enchantment"
}
```

### 命名规范

- **方块**: `block.pasterdream.<注册名>`
- **物品**: `item.pasterdream.<注册名>`
- **实体**: `entity.pasterdream.<注册名>`
- **效果**: `pasterdream.effect.<注册名>`
- **音效**: `pasterdream.sound.<注册名>`
