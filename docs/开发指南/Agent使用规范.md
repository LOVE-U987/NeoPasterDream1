# AI 辅助开发规范（Agent 使用规范）

> 适用对象：所有使用 AI 编码助手参与本项目开发的贡献者
> 工具无关：不限定特定 AI 工具（opencode / Claude Code / Cursor / Copilot 等均可）
> 分工：本文档 = 通用规范；[AGENTS.md](../../AGENTS.md) = 项目级行为契约；个人 AI 工作区配置 = 开发者私有

---

## 1. 规则分层

本项目对 AI 辅助开发采用三层规则体系：

| 层级 | 位置 | 是否入库 | 适用范围 | 说明 |
|------|------|:------:|---------|------|
| **项目级契约** | 根目录 `AGENTS.md` | ✅ 随仓库分发 | 所有开发者与其 AI | AI 行为规则 + 任务路由表 |
| **通用规范** | `docs/` | ✅ | 所有人 | 本文档与各专项规范 |
| **个人工作区** | `.opencode/`、`.claude/` 等本地目录 | ❌ gitignore（`### AI tools ###` 段） | 仅本人 | 个人规则/子代理/命令 |

**约束关系**：项目规范条款按效力分三类，个人规则的覆盖权限以此为准：

| 类别 | 判定 | 个人规则权限 |
|------|------|-------------|
| **禁止** | 条款使用「禁止 / 必须 / 不得」措辞（如禁止事项、注册必须 `DeferredRegister`、LF 换行） | 不得覆盖或放宽，冲突时以项目规范为准 |
| **允许** | 条款使用「推荐 / 允许 / 建议」措辞（如 MD 文件允许 Emoji、注释推荐中文、行长推荐 120） | 可选收紧或改向，以个人规则为准 |
| **未界定** | 项目规范未提及的领域（如方法行数上限、沟通语言、工具偏好） | 完全由个人规则决定 |

- 个人规则中不得包含违反「禁止」类条款的授权
- 个人配置不入库，不会进入仓库，也不影响他人

## 2. AI Agent 必守项目规则

以下为摘要，完整规则见 [AGENTS.md](../../AGENTS.md)。所有 AI 工具都应在任务开始时加载该文件。

### 2.1 任务启动

1. 读取并遵守 `AGENTS.md` 全部规则
2. 涉及具体系统时，先查 `AGENTS.md` 的「任务类型 → 必读文档」路由表，再动手

### 2.2 行为边界（禁止事项）

- 不修改 `libs/`（原模组只读参考）
- 不复制 MCreator 代码（经原作者正式授权的移植采用基于 NeoForge 1.21.1 API 的手写重实现）
- 不做任何 Git 提交/推送/暂存等状态变更操作
- 不硬编码配置
- 不跳过 DataGen
- 不忽略编译错误

### 2.3 硬性技术规则

| 规则 | 文档 |
|------|------|
| 换行符 LF（`.bat` 除外）、UTF-8 无 BOM | [代码规范](代码规范.md) |
| 注册必须 `DeferredRegister`、注册名 snake_case | [注册指南](注册指南.md) |
| GeckoLib 目录 entity/block/item 分置 | [资源规范](资源规范.md) |
| 战利品表 1.21 新格式（`loot_table` 单数 + `predicates` 包装） | [问题排查](问题排查.md) |
| 模块归属决策（API/主模块边界） | [模块边界](../架构/模块边界.md) |

### 2.4 验证要求

AI 修改代码后必须验证，与人类贡献者标准一致：

```bash
.\gradlew compileJava   # 编译通过（最低要求）
.\gradlew runData       # 涉及数据文件时
.\gradlew runClient     # 功能验证
```

详见 [测试指南](测试指南.md)。

## 3. 个人 AI 工作区指引

### 3.1 允许个性化

开发者可在本地建立自己的 AI 工作区，自由配置：

- 个人规则文件（沟通风格、工具偏好等）
- 自定义子代理（如只读审计、计划审核等辅助角色）
- 自定义命令、计划文件目录

此类配置不入库，仅约束本人。

### 3.2 约束

- 个人规则对项目条款的覆盖权限按 §1 三类口径执行：「禁止」类不得覆盖；「允许」类可选收紧或改向；「未界定」领域由个人规则决定
- 个人规则中不得包含违反「禁止」类条款的授权（如允许 Git 状态变更、允许修改 `libs/`、放宽换行符要求）

### 3.3 建议实践（可选采用）

以下为经过实践验证的工作流模式，推荐但不强制：

1. **计划先行**：复杂任务先在计划模式生成计划文件，明确步骤与验收标准
2. **只读审核**：计划执行前由只读子代理审核完整性与合规性
3. **执行与验证**：按计划逐步实现，统一用 `compileJava` 验证
4. **对照审计**：完成后由只读子代理对照计划逐项验证

> 单文件小改动可直接执行，无需完整流程。

## 4. AI 生成内容的提交注意点

- AI 生成的代码**同样适用** [代码规范](代码规范.md)，审查标准不降低
- 提交信息遵循 [Git 规范](Git规范.md)，由人类开发者确认后提交
- **禁止提交**：个人工作区文件、secrets/密钥、构建产物
- AI 的所有变更最终由提交者负责，提交前应人工审查 diff
