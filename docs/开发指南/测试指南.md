# 测试指南

> 本文档说明测试驱动的开发与验收流程,以及编译、数据生成、VERIFY 和游戏实测的使用方法。以下 Windows 命令以 PowerShell 为例。

---

## 测试须知

推送或合并前,必须完成全量编译、相关 VERIFY 验证和实际游戏测试；涉及数据文件时必须运行 DataGen。编译失败或相关验收项失败不得以游戏能启动代替。Agent 产出的代码还需二次审查,并确认模块归属符合架构规范。

## 测试驱动流程

1. **定义行为**：写清触发条件、预期结果和边界情况；修复 Bug 时先记录可复现的失败场景。选择现有 VERIFY 套件,或为新行为补充可执行的验证钩子。
2. **确认失败**：在实现前运行相关验证,确认它因目标行为缺失而失败。若只能在游戏中复现,记录具体操作与观察结果。不能让测试因环境、资源缺失等无关原因失败来充当基线。
3. **实现并转绿**：只实现满足验收条件所需的代码；先编译,再运行目标 VERIFY 套件和相关 DataGen。检查报告中的失败与跳过项,不能把 `SKIP` 当作通过。
4. **重构与回归**：清理实现后重跑目标验证,随后全量编译并按影响范围运行相邻套件。启动游戏实际检查交互、资源和客户端/服务端行为。
5. **记录证据**：在 PR 中写明失败基线、验证命令、套件结果、手测步骤及未覆盖的限制。无可自动化验证的行为,至少写出可重复的手测步骤。

`compileJava` 只证明代码可编译；`runData` 只证明数据生成流程执行；VERIFY 检查具体行为；`runClient` / `runServer` 的实际操作才检查游戏内表现。各步骤不能互相替代。

---

## 测试类型

| 类型 | 命令 | 说明 |
|------|------|------|
| 编译测试 | `.\gradlew compileJava` | 检查代码是否能编译 |
| 数据生成 | `.\gradlew runData` | 生成数据文件 |
| 客户端测试 | `.\gradlew runClient` | 启动游戏客户端 |
| 服务器测试 | `.\gradlew runServer` | 启动游戏服务器 |
| VERIFY 系统 | PowerShell 环境变量 + `:PasterDream:runClient` | 自动化功能验证；须选择目标套件 |

## 编译测试

### 全量编译

```bash
# 编译所有模块
.\gradlew compileJava
```

### 单模块编译

```bash
# 编译主模块
.\gradlew :PasterDream:compileJava

# 编译 API 模块
.\gradlew :PasterDreamAPI:compileJava

# 编译法术模块
.\gradlew :PasterDreamSpells:compileJava

# 编译理智模块
.\gradlew :PasterDreamSanity:compileJava

# 编译融梦模块
.\gradlew :PasterDreamMeltDream:compileJava
```

### 清理构建

```bash
# 清理构建缓存
.\gradlew clean

# 清理后重新编译
.\gradlew clean compileJava
```

## 数据生成

```bash
# 运行数据生成器
.\gradlew runData
```

数据生成器会生成:
- 方块标签
- 方块模型
- 其他数据文件

**注意**: 涉及 DataGen 的注册、资源或数据变更后,需重新运行数据生成器,检查生成内容,再到游戏中验证加载与行为。

## 客户端测试

```bash
# 启动客户端
.\gradlew runClient
```

### 测试要点

1. **启动检查**: 游戏能否正常启动
2. **资源加载**: 纹理、模型、动画是否正确加载
3. **功能测试**: 新添加的功能是否正常工作
4. **性能测试**: 是否有明显的性能问题

### 常见问题

| 问题 | 可能原因 | 解决方案 |
|------|---------|---------|
| 紫黑纹理 | 模型/纹理路径错误 | 检查 GeckoLib 目录结构 |
| 动画不播放 | 动画文件路径错误 | 检查 `animations/` 目录 |
| 崩溃 | 代码错误 | 查看日志,定位问题 |

## VERIFY 系统

VERIFY 是 PasterDream 的自动化功能验证系统,用于确保各系统按预期工作。

### 运行 VERIFY（Windows PowerShell）

```powershell
# 默认 all：运行基础集合,不包含部分专项套件
$env:PASTERDREAM_VERIFY = '1'
Remove-Item Env:PASTERDREAM_VERIFY_SUITES -ErrorAction SilentlyContinue
.\gradlew :PasterDream:runClient

# 显式选择与改动相关的套件；多个套件用逗号分隔
$env:PASTERDREAM_VERIFY_SUITES = 'core,wind-journey'
.\gradlew :PasterDream:runClient

# 完成后清除本终端会话中的设置
Remove-Item Env:PASTERDREAM_VERIFY,Env:PASTERDREAM_VERIFY_SUITES -ErrorAction SilentlyContinue
```

环境变量只影响当前 PowerShell 会话。单个套件可将 `PASTERDREAM_VERIFY_SUITES` 设为 `core` 等名称。VERIFY 默认保持客户端打开供人工观察；自动退出可设置 `$env:PASTERDREAM_VERIFY_KEEP_OPEN = '0'`。

### VERIFY 套件

| 套件 | 说明 |
|------|------|
| `core` | 核心属性、附件、效果等行为验证 |
| `wind-journey` | 风之旅途维度验证 |
| `twilight-lantern` | 暮影提灯验证 |
| `second-dream` | 第二梦境验证 |
| `main-flow` | 主流程验证 |
| `dyedream` | 染梦维度验证 |
| `all` | 默认基础集合；不包含下述专项套件 |

`twilight-lantern`、`wind-journey`、`second-dream`、`shadow-intrude`、`main-flow`、`dyedream` 等专项不在默认 `all` 中,必须显式指定。`arena-exit`、`wind-lake`、`san-tick` 等也需按相关钩子说明显式启用。完整套件名称、组合与排除规则以 `PasterDream/src/main/java/com/pasterdream/pasterdreammod/smoketest/PDPortingVerifyTest.java` 的 `Suite` 定义为准。

### VERIFY 报告

验证结果保存在:
- 控制台输出
- 主模块运行目录中的 `pd_verify_report.json`（通常为 `PasterDream/run/pd_verify_report.json`）

核对实际运行目录、套件名称以及每个断言的 `PASS` / `FAIL` / `SKIP`；专项验证中的跳过项还需在适合的世界条件下手测。

### 常用 IDE 运行配置

- `PD SMOKETEST+VERIFY` — 运行预设验证
- `PD VERIFY quick` — 运行 registry + core
- `PD VERIFY wind-journey` — 运行风之旅途验证
- `PD VERIFY main-flow` — 运行主流程验证

---

## 添加或修改 VERIFY 验证

现有验证位于主模块 `smoketest/` 包,由 `PDPortingVerifyTest` 调度各 `*VerifyHooks`。先查看相近套件的触发条件、断言和结果记录方式；新套件需接入 `Suite` 的解析与调度,并明确是否加入默认 `all`。仓库没有通用 `PDVerify.assert*` 工具类或 `@VerifySuite` 注解,不要按旧示例实现。

## 常见问题

### Q: 编译失败怎么办?

1. 检查 Java 版本是否为 21
2. 运行 `.\gradlew clean` 清理构建缓存
3. 查看错误信息,定位问题文件
4. 参考 [问题排查](问题排查.md)

### Q: VERIFY 失败怎么办?

1. 查看控制台输出,定位失败的断言
2. 检查相关代码是否正确
3. 运行单个套件进行测试
4. 查看实际主模块运行目录中的 `pd_verify_report.json` 获取详细信息,区分失败与跳过

### Q: 如何添加新的 VERIFY 套件?

1. 在主模块 `smoketest/` 中参考相近的 `*VerifyHooks` 实现失败基线与结果记录
2. 在 `PDPortingVerifyTest.Suite` 中登记名称、别名与是否纳入默认集合
3. 接入调度,运行单个新套件并检查报告与游戏内行为

### Q: 如何运行特定实体的测试?

```bash
# 使用 /summon 命令
/summon pasterdream:shadow_golem ~ ~ ~

# 使用 /effect 命令
/effect give @s pasterdream:my_effect 3600 0
```
