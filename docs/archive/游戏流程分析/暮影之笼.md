## 0. 一句话

主世界 **structure_set `shadow_world_doors`（concentric_rings）+ jigsaw `shadow_world_door`** 自然生成含笼子 + 真影床的据点；  
笔记 8/9 坐标经 **`PDShadowDoorLocator` → `findNearestMapStructure`**；  
满足笔记成就后用 **融梦水晶碎片** 点燃 → **约 130s「据点守卫」刷怪** → `key=true` + `achievement_hide_9` →  
**夜晚/雷暴**在床上、且床上方 2 格笼子已激活 → 进 **灯影世界**；灯影内再右键笼子 → **主世界重生点/出生点**（不依赖裸 `/spawn`）。

> **生存链路（2026-07-28 收口 · VERIFY 2026-07-29 36/0 · 自然档 locate 手测 2026-07-30 过）**：主世界 **structure_set + locate**；灯影 **`PDLampShadowWorldgen` 放 spawn**；**Warden→hide_7**；返程重生点传送。`structure_block_9` / 杖仍为调试旁路。  
> **`ANIMATION`：预期如此 · 仅 idle `"0"`**（有意不驱动 oneshot）→ [`功能状态.md` §3.2b](../../功能状态.md#32b-预期如此--有意不做不是缺口勿当待办)。可选 rings 调参 → §3.2。设计/历史：见 `docs/superpowers/specs/`（部分 plan 已清理）。

## 1. 世界生成（方块从哪来）

笼子**没有**独立的 ore / placed_feature。它嵌在结构 NBT 里。

### 1.1 主世界据点：「暮影之笼」结构

| 项 | 值 |
| :--- | :--- |
| 自然生成 | `worldgen/structure/shadow_world_door.json`（`minecraft:jigsaw`） |
| structure_set | `worldgen/structure_set/shadow_world_doors.json` → **`concentric_rings`** |
| template_pool | `worldgen/template_pool/shadow_world_door.json` → NBT `shadow_world_door` |
| 模板路径 | `data/pasterdream/structure/shadow_world_door.nbt` |
| 深度 | `start_height.absolute = -60`；`step: underground_structures` |
| locate tag | `#pasterdream:twilight_lantern_located` |
| 坐标 API | `PDShadowDoorLocator.locate(ServerLevel, BlockPos[, radius])` |
| 笔记 8/9 | **全 locate**；**不再**用 `randomCoord*21`（gamerule 仍注册、不驱动门） |
| 调试旁路 | `structure_block_9`（SPECS 9）/ 调试杖按名放置 |

**原版对照（有意分叉）**：`GenerateWorldPr0Procedure` @ Load 用 `randomCoordX/Z` 强制 `placeInWorld` 一份，**不能** `/locate`。  
**Neo**：chunkgen 可多座；locate 取最近；散布由 rings 参数决定（默认可后调）。

模板内已确认含（字符串扫描 NBT）：

- `pasterdream:twilight_lantern`
- `pasterdream:true_shadow_bed`
- 影石砖/厚影/影烛等建筑块

调试：`structure_block_9` 放置后（+10t 循环兜底）`placeInWorld` 整包模板，触发块自毁为空气（与其它 structure_block_0..23 一致）。

### 1.2 灯影世界出生点

| 项 | 值 |
| :--- | :--- |
| 模板 | `shadow_world_spawn.nbt`（含返程 `twilight_lantern`） |

床传送落点仍为 `(0.5, 104|154, 0.5)`（`WorldSpawnPr1` 语义）。

## 3. 主世界：据点守卫事件

实现：`useWithoutItem`（原 Pr0）+ `tick`（原 Pr1）+ `spawnGhostWave`（原 Pr2）。

### 3.1 启动条件

全部需要：

1. **不在** `lamp_shadow_world`（主世界侧分支）
2. 成就 **`achievement_hide_8` 或 `achievement_hide_10`** 已完成  
3. 主手为 **`meltdream_crystal_0`（融梦水晶碎片）**  
4. 当前 **`switch == false`**（未在事件中）

| 失败提示 | 原因 |
| :--- | :--- |
| 「你尚未知晓如何激活影灯」 | 无 hide_8 / hide_10 |
| 「需要用融梦水晶碎片点燃影灯」 | 有成就但主手不对，或已在 switch |

#### 成就从哪来（笔记）

| 成就 | 来源（摘要） |
| :--- | :--- |
| `achievement_hide_8` | `dreamnotes_8`：已有 `hide_7` 时阅读解锁（「阴影中的潜藏者」）；背面坐标等 |
| `achievement_hide_10` | `dreamnotes_9`：已有 `achievement_b_0` 时阅读解锁（「侵染教堂」）等 |
| `achievement_hide_9` | **事件成功结束**时由笼子授予（见 3.3），不是笔记直接给 |

### 3.2 点燃瞬间

1. 玩家 **黑暗** 140 tick  
2. `switch = true`  
3. 从背包扣 **1** 融梦水晶碎片  
4. 灯笼放置音 + `END_ROD` 粒子（中心附近）  
5. **+18 t**：音效 `SHADOW_0` + 文案「诡异的灯笼突然剧烈抖动…」  
6. **+55 t**：音效 `SHADOW_MUSIC_0`（MUSIC）+ 文案「阴影化为实物…」  
7. **+2600 t**（≈ **130 s**）：结束判定（§3.3）

事件期间 `tick` 每 20t 调度；`switch` 为 true 时 `number++` 并按节点刷怪。

### 3.3 结束（t+2600）

```
若 46×46×46 范围内仍有玩家:
    key = true
    对附近实体（inflate 约 27 格量级，代码 AABB inflate 54/2）中的玩家:
        立即: 「阴影不再…暮影之笼也逐渐归为平静」
        +60t: 「躺上去吧，在寂静的夜晚，在这亭笼之下」
              「已可以与暮影之笼发生共鸣」(actionbar)
        +100t: 授予 achievement_hide_9
一律: switch = false
```

若结束时 46 格内**没有**玩家：不置 `key`、不授 hide_9，仍关 `switch`（可再次点燃，需再耗碎片）。

### 3.4 刷怪时间表（`number`，单位 = 20 tick 周期）

仅当 `switch == true`：

| number | 召唤 |
| -----: | :--- |
| 4, 14, 40, 50, 70, 100, 120 | **幽魂波** `spawnGhostWave` |
| 30 | 暗影傀儡 `(x, y-1, z+13)` + 惧喙 `(x-13, y-1, z)` |
| 80 | 暗影傀儡 `(x, y-1, z-13)` + 惧喙 `(x-13, y-1, z)` |

坐标均相对**笼子方块** `pos`。

#### 幽魂波构成（相对笼子）

| 实体 | 数量 | 位置模式 |
| :--- | ---: | :--- |
| `SHADOW_GHOST` 暗影幽魂 | 4 | `(±6, y+2, z)`、`(x, y+2, z-6)`×2（**z-6 写两次，与原版一致**） |
| `SHADOW_SQUEAL_GHOST` 尖啸幽魂 | 4 | `(±8, y+1, ±8)` 四角 |
| `WITHER_SKELETON` 凋灵骷髅 | 4 | `(±9, y-1, z+1)`、`(x, y-1, ±9)` |

生成类型：`MobSpawnType.MOB_SUMMONED`。

放置后 `onPlace` 即 `scheduleTick(20)`；事件外仍每 20t 空转 schedule，不涨 `number`。

## 4. 真影床 → 灯影世界

实现：`TrueShadowBedBlock`（结构内是 **`true_shadow_bed`**，不是普通 `shadow_bed`）。

进维条件（摘要，与类注释一致）：

1. **夜晚或雷暴**  
2. 床**上方 2 格**是暮影之笼，且其 BE **`key == true`**  
3. 玩家已完成 **`achievement_hide_9`**  
4. 满足时：**理智 -10**，传送至 **`lamp_shadow_world`**

白天：提示只能夜晚入眠。  

灯影内额外：若已 `achievement_shadow_npc_5` 且未 `achievement_shadow_d_0`，右键床可开 **影之抉择**（`ShadowSelectEndMenu`）——与进维是另一条分支。

自制 **`shadow_bed`（暮影长床）** 为后续常规入口（成就/配方链，见功能状态与图鉴）；首次据点流程依赖结构里的真影床 + 笼 `key`。

图鉴文案（`pasterdream.entry.lamp_shadow_world.page2`）：

> 在暮影之笼影结构中，完成「据点守卫」事件后，即可通过暮影长床前往灯影之下。此后，可以自行制作暮影长床进入灯影之下。

## 5. 灯影世界：返程

维度：`pasterdream:lamp_shadow_world`（`PDDimensions.LAMP_SHADOW_WORLD_LEVEL_KEY`）。

右键笼子（任意手物品路径走 `useWithoutItem`）：

1. 灯笼放置音  
2. **+20 t** 后：`teleportToOverworldSpawn`  
   - WIN_GAME 过场（若不在主世界）  
   - `teleportTo(overworld)` 至 **玩家主世界重生点**，否则 **世界共享出生点**（heightmap）  
   - 同步能力 / 效果 / 维度事件包 1032  
   - **不再**执行裸命令 `spawn`

返程**不**检查 `key` / 碎片 / 成就。

## 10. 已知实现细节（与原版对齐）

- 幽魂波 `z-6` 暗影幽魂生成了**两次**同一相对坐标——与原版 procedure 一致，非移植笔误。  
- 结束检测「46 格内有玩家」与发奖用的 inflate 范围不完全同一公式，但均为「笼附近玩家」。  
- `number` 用 double 存储、与 int 节点比较——与原版 MCreator 数据键一致。  
- 返程：`teleportToOverworldSpawn`（重生点优先，否则共享出生点）；**不**再依赖裸 `/spawn`（相对原版字面命令的有意改进）。
