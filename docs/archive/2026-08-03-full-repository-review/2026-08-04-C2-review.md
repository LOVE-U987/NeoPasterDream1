# C2 详细审查报告 — 盔甲套装效果 `removeEffect` 剥外来 buff

> 日期：2026-08-04
> 关联：[`fix-comparison-table.md`](fix-comparison-table.md) C2-1 ~ C2-6
> 性质：**临时文件**，本报告为本次审查（调用逻辑梳理 + 实际游戏测试）发现的 C2 相关 bug 拆分说明。

---

## 1. 结论摘要

原 C2「Sculk/Titanium/Dyedream/Copper 盔甲 `removeEffect` 剥外来 buff」经调用逻辑梳理与**实际游戏测试确认**，并非单一问题，拆分为 6 个子 bug：

| ID | 问题本质 | 实测/复现 | 严重度 |
|---|---|---|---|
| C2-1 | `inventoryTick` 无「护甲槽归属」守卫 → **背包持有即触发** | ✅ 实测复现 | Critical |
| C2-2 | 非满套 else-分支 `removeEffect` 无条件剥外来同名 buff | ✅ 实测复现 | Critical |
| C2-3 | 四件各自每 tick 重复执行全套检查（无单点） | 代码确认 | Medium |
| C2-4 | 满套 `addEffect` 无条件重加弱效果，覆盖外来更强效果 | 代码确认 | Medium |
| C2-5 | Copper 满套剥 `DIG_SLOWDOWN`，连主动饮用的挖掘疲劳药水也剥 | 设计争议，待产品审核 | Medium |
| C2-6 | 孤儿效果 `DYEDREAM/SCULK_ARMOR_BUFF` + `armorBuffRemove` 同模式 removeEffect | 代码确认（当前不生效） | Low |

---

## 2. 调用链梳理

```
MinecraftServer 每 tick
  └─ Player.tick() → Inventory.tick()
       └─ 遍历全部背包槽(主手36 + 护甲4 + 副手) → ItemStack.inventoryTick()
            └─ Sculk/Titanium/Dyedream/CopperArmorItem.inventoryTick()   [各件各自触发]
                 └─ checkAndApplySetEffect(entity)   ← 唯一入口，private，无其他调用方
                      ├─ hasFullSet ? addEffect(短时效) : removeEffect(同名buff)
                      └─ Copper: hasFullSet ? removeEffect(DIG_SLOWDOWN)
```

- 注册侧：`registry/items/PDItemsArmor.java:43-80` 注册 16 件 → 聚合引用 `registry/PDItems.java:735-750`。
- 效果实际运行时**只有**上述 `inventoryTick` 路径生效。
- `registry/PDEffects.java:389,579` 定义的 `DYEDREAM_ARMOR_BUFF` / `SCULK_ARMOR_BUFF`（含 onTick/onRemove）**注册但全库无任何应用方**（孤儿/死代码），当前不参与运行时。
- `checkAndApplySetEffect` 为各 ArmorItem 私有方法，无事件监听或其他调用方。

## 3. 子 bug 详情

### C2-1 背包持有即触发（无护甲槽归属守卫）

**位置**：`item/SculkArmorItem.java:49-54`、`TitaniumArmorItem.java:49-54`、`DyedreamArmorItem.java:53-58`、`CopperArmorItem.java:48-53`（`inventoryTick`）。

**根因**：vanilla 会对玩家**全部背包槽**调用 `inventoryTick`，新实现未校验「当前 itemstack 是否实际穿在护甲槽」。

**复现（实测确认）**：玩家背包**携带**一件潜声/钛/染梦盔甲（未穿戴）→ 每 tick 进入 `checkAndApplySetEffect` → 非满套 → 执行 else-分支 `removeEffect` → **药水隐身/夜视/生命提升被立刻剥掉**。

**对照**：原版 MCreator 代码有 `Iterables.contains(player.getArmorSlots(), itemstack)` 守卫（`libs/.../item/SculkArmorItem.java:99`、`DyedreamArmorItem.java:94`）。

**修复思路**：`inventoryTick` 内增加护甲槽归属判断，仅当该 stack 实际穿在对应护甲槽时才执行套装检查。

### C2-2 非满套 else-分支剥外来同名 buff

**位置**：`item/SculkArmorItem.java:44`、`TitaniumArmorItem.java:44`、`DyedreamArmorItem.java:48`。

**根因**：`if (hasFullSet) addEffect(...); else entity.removeEffect(INVISIBILITY|NIGHT_VISION|HEALTH_BOOST)` —— `removeEffect` 不区分效果来源，任何药水/信标/其他来源的同名效果都会被剥掉。

**复现（实测确认）**：穿单件对应盔甲 + 喝隐身/夜视/生命提升药水 → 药水效果立刻消失（配合 C2-1 触发条件，仅携带亦复现）。

**修复思路**：删除 else-分支的 `removeEffect`；满套仅 `addEffect` 短时效刷新，脱套后效果自然过期（≤10 tick）。

### C2-3 四件各自每 tick 重复执行全套检查

**位置**：4 个 ArmorItem 的 `inventoryTick`。

**根因**：四件护甲各自覆写 `inventoryTick` 且均执行完整套装检查，满套时每 tick 重复 4 次（携带多件时更多）。

**对照**：`item/QymArmorItem.java:56` 已收敛到头盔单点（`if (this.getType() != HELMET) return;`）。

**修复思路**：触发点统一收敛到头盔单点。

### C2-4 满套 `addEffect` 无条件重加弱效果覆盖外来更强效果

**位置**：`item/SculkArmorItem.java:41`、`TitaniumArmorItem.java:41`、`DyedreamArmorItem.java:41`。

**根因**：满套时每 tick `addEffect(同名效果, 10, 0)`，会**覆盖**玩家已有的更高等级/更长时长的外来同名效果（如药水隐身 II → 被降级为 0 级 10 tick）。

**对照**：原版 `HealthboostArmorPr0Procedure.java` 有 `!hasEffect` 守卫（`libs/.../procedures/HealthboostArmorPr0Procedure.java:12`）。

**修复思路**：仿原版加 `!hasEffect` 守卫，仅在缺失时补挂短时效效果。

### C2-5 Copper 满套剥 DIG_SLOWDOWN（设计争议）

**位置**：`item/CopperArmorItem.java:43`。

**说明**：满套时 `removeEffect(DIG_SLOWDOWN)` 为「挖掘疲劳免疫」设计意图，与 C2-2 的 else-分支性质不同。争议点：会连玩家**主动饮用的**挖掘疲劳药水也一并剥掉。

**状态**：**待产品审核**，暂不列入本期修复范围。

### C2-6 孤儿效果同模式 removeEffect 残留

**位置**：`registry/PDEffects.java:389-397`（DYEDREAM_ARMOR_BUFF）、`:579-587`（SCULK_ARMOR_BUFF）、`:881-890`（`armorBuffRemove`）。

**说明**：两个 `_armor_buff` 效果已注册（含 `onRemove` → `armorBuffRemove` → 非满套时 `removeEffect(HEALTH_BOOST)`），但**全库无应用方**。若未来接线启用，将重演 C2-2 的剥外来 buff 问题。

**修复思路**：清理或修正 `armorBuffRemove` 为不剥外来效果（对齐 C2-2 修复后的语义）。

## 4. 附带发现（范围外，仅提示）

**`QymArmorItem` 同样缺护甲槽归属守卫**：`item/QymArmorItem.java:50-64` 的 `inventoryTick` 仅判断头盔单点，未校验护甲槽归属 → 背包持有 Qym 头盔亦会每 tick 执行 `SanHelper.setPlayerSanWithCheck(player, 100)`（San 回满）。不剥 buff（只 add），但存在无谓执行与潜在存档数据写入。

---

## 5. 与原版设计偏离（非 bug，需产品确认）

| 项 | 原版（libs 参考） | 现实现 |
|---|---|---|
| Sculk 套装效果 | 生命提升 + 抗黑暗 + y<0 抗性（**非隐身**） | 隐身 |
| 套装件数 | 三件套（靴+腿+胸，头盔为触发点） | 四件套 |
| 触发点 | 头盔单点 + 护甲槽守卫 | 四件各自 + 无守卫 |
| Titanium/Copper | **原版无套装效果** | 新增夜视 / 挖掘疲劳免疫 |
| 触发守卫 | `Iterables.contains(getArmorSlots(), itemstack)` | 无 |

---

## 6. 修复优先级建议

1. **C2-1 + C2-2**（实测根因，剥 buff）→ 最先修复；
2. **C2-3**（单点收敛，顺带性能）→ 随 C2-1/C2-2 一并；
3. **C2-4**（addEffect 守卫）→ 随 C2-2 顺带；
4. **C2-5 / C2-6** → 待产品审核 / 择机清理。
