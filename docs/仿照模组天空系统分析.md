## 2. 架构总览

Stellara 采用**三层架构**：

```
┌─────────────────────────────────────────────────────────────────┐
│ 数据层   data/<modid>/skyboxes/*.json                            │
│         SkyboxDataReloadListener (SimpleJsonResourceReloadListener)│
└──────────────────────────────┬──────────────────────────────────┘
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│ 注册/条件层  SkyboxRegistry (代码注册 + 数据条目合并)              │
│             SkyboxEntry(content, condition, fadeSpeed, weight)   │
│             SkyboxCondition (biome/biomeTag/dimension/time 组合)  │
└──────────────────────────────┬──────────────────────────────────┘
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│ 渲染层     LevelRendererMixin 注入 LevelRenderer#renderSky       │
│            StellaraSkyboxRenderer（候选选择 + 淡入淡出 + 逐层绘制） │
│            SkyboxContent 实现 ×8（tint/star/planet/constellation/│
│            shootingStar/aurora/ribbon/rainbow）                  │
└─────────────────────────────────────────────────────────────────┘
```

**核心思想**：一个 JSON 定义一套"天空盒"，由多个 `layers`（图层）组成；每个图层是一个独立 `SkyboxEntry`（自带条件、权重、淡入速度），运行时按 `weight` 选出唯一活跃候选，逐帧把候选内所有图层按 `priority` 排序绘制。

## 3. 核心渲染机制

### 3.1 注入点（`LevelRendererMixin`）

```java
@Mixin(LevelRenderer.class)
public class LevelRendererMixin {
  // ① @Redirect：抑制原版星星（第 2 次 VertexBuffer.drawWithShader，ordinal=1 即星盘）
  //    当 Stellara 有活跃天空盒时跳过原版星星绘制，避免双重星空
  @Redirect(method = "renderSky", at = @At(value = "INVOKE",
      target = "...VertexBuffer;drawWithShader(...)V", ordinal = 1))
  private void stellara$suppressVanillaStars(...) { ... }

  // ② @Inject(RETURN)：在 renderSky 末尾调用 StellaraSkyboxRenderer.render
  @Inject(method = "renderSky", at = @At("RETURN"))
  private void stellara$renderSkybox(...) { StellaraSkyboxRenderer.render(poseStack, camera, partialTick); }
}
```

> renderSky 内的 `drawWithShader` 共 2 次：ordinal 0 = 日月 buffer，ordinal 1 = 星盘 buffer。

### 3.2 渲染器流程（`StellaraSkyboxRenderer`，纯静态）

```
render() 
  → makeContext()     构建 SkyboxRenderContext（见 3.3）
  → updateSelectedCandidate()  候选切换
  → 设置状态：depthMask(false) + enableDepthTest + enableBlend(标准 alpha)
  → PoseStack 旋转：-90°(X) 然后 skyAngle(Y)   ← 让天空随昼夜旋转
  → 遍历所有 entries（按 priority 排序）：
      targetAlpha = 匹配候选 ? content.targetAlpha(context) : 0
      nextAlpha   = lerp(currentAlpha, targetAlpha, fadeSpeed * max(partialTick, 0.25))
      if (nextAlpha > 0) content.render(context, nextAlpha)
```

**候选切换防抖**：`rawCandidate` 选"条件匹配 + targetAlpha>0.003 + weight 最高"的 entry；切换时进入 `pendingSince`，连续 60 tick 目标不变才生效，防止玩家跨群系边界时天空抖动；`ALPHAS` map 记录每 entry 当前透明度实现**交叉淡入淡出**。

**候选判定**（`Candidate` = contentId 去掉 `/layer_N` 后缀 + weight）：
- 同一 JSON 的多个 layer 共享同一候选键 → 整套天空盒整体切换，图层间无切换竞争。

### 3.3 SkyboxRenderContext（每帧上下文快照）

| 字段 | 来源 | 说明 |
|------|------|------|
| `minecraft` / `level` / `camera` / `poseStack` | 渲染现场 | — |
| `partialTick` / `renderTime` | `level.gameTime + partialTick` | 动画时间基准（秒） |
| `skyAngle` | `timeOfDay * 360` | 天空旋转角 |
| `dayTime` | `level.getDayTime() % 24000 + partialTick` | 用于时间窗判断 |
| `visibility` | `nightFactor * weatherFactor * occlusion` | 总可见度 |
| `nightFactor` | 主世界=星亮度×2；末地恒 1 | 夜晚才亮 |
| `weatherFactor` | `1 - rainLevel*0.65` | 雨天变暗 |
| `biome` / `biomeKey` | 相机所在方块位置的群系 | 群系差异核心 |

**可见性门槛**：`hasSupportedSky()` 只支持 `SkyType.NORMAL`（主世界）与 `SkyType.END`（末地）两种天空类型；水下/岩浆/失明时 `occlusion=0` 不渲染。

### 3.4 单位球几何（`SkyGeometry` / `SkyPoint`）

- 所有天体定位在**半径 100 的单位球**上：`point(yaw, pitch) = (sin(yaw)*cos(pitch), sin(pitch), cos(yaw)*cos(pitch)) * 100`。
- `addBillboard`：广告牌四边形（面向球心），支持纹理 UV、自旋角度、颜色 alpha。
- `addLine`：两点间的宽线段（星座连线用），法线 = 中点叉积。
- `SKY_RADIUS = 100`（与 vanilla 星空半径一致，正好替换原版星盘）。

## 4. 八种天空内容实现

所有内容实现 `SkyboxContent` 接口：`id()` / `priority()` / `targetAlpha(context)`（默认=visibility）/ `render(context, alpha)`。
JSON 中通过 `"type": "stellara:<类型>"` 分派，解析在 `SkyboxDataReloadListener.parse()` 的 switch 中。

### 4.1 `sky_tint` 天空色彩（SkyTintContent）

- **JSON**：`color`（RGB 0~1）、`opacity`。
- **实现**：`POSITION_COLOR` 格式绘制半径 100 的**六面立方体包围盒**，整球统一着色（单色 tint，靠 alpha 控制强度）。
- **用法**：priority=-100 打底，给整片夜空染上主题色（如末地暗紫、海洋深蓝）。

### 4.2 `star_field` 星空（StarFieldSkyContent）

- **JSON**：`textures`（7 帧动画列表，可多色组）、`count`、`min/max_size`、`color`、`seed`。
- **实现**：
  - 构造时用 `LegacyRandomSource(seed)` 生成 N 颗星：单位球随机点（经 `StarClusters` 聚团分布，见下）、大小、角度、脉动相位/速度、自旋速度、随机纹理帧。
  - 每帧：逐纹理批次绘制 `POSITION_TEX_COLOR` QUADS 广告牌；`pulse = 0.78 + 0.22*sin(renderTime*pulseSpeed + offset)` 呼吸闪烁；广告牌自旋 `angle + renderTime*spinSpeed`。
- **`StarClusters`**：用噪声（LegacyRandomSource 的 nextInt/nextFloat 多次采样构造聚类中心 + 高斯偏移）让星星**成群聚团**，模拟银河/星云感，而非均匀撒点。

### 4.3 `planet_system` 行星+卫星（TexturedPlanetSystemSkyContent）

- **JSON**：`planets[]`，每个含 `texture/yaw/pitch/size/roll/roll_speed/color/opacity` 与可选 `satellites[]`（`texture/size/orbit_radius/orbit_speed/orbit_offset/roll/color/opacity`）。
- **实现**：
  - 行星：`addTexturedBillboard` 静态广告牌，`roll + renderTime*rollSpeed` 自转。
  - 卫星：以行星中心为原点，构造**切空间**（单位法线 → 正交切/副切向量），按 `orbitAngle = orbitOffset + renderTime*orbitSpeed` 在切平面圆周运动，投影回半径 100 球面（重归一化），再 billboard 绘制 → 实现"卫星绕行星公转"的视觉。

### 4.4 `constellation` 星座（ConstellationSkyContent）

- **JSON**：`center_yaw/center_pitch/scale/twinkle_speed/line_width/textures` + `nodes[]`（`u/v/size`）+ `links[]`（`from/to`）。
- **实现**：
  - 节点→单位球坐标：`point(centerYaw + u*scale, centerPitch + v*scale)`，构成星座图案骨架。
  - 连线：`addLine` 宽线段，加法混合（`SRC_ALPHA, ONE`）。
  - 星点：双层 billboard —— 外圈 `color` 大光晕（α×0.5）+ 内圈 `coreColor`（提亮 55%）核心，随 `twinkleSpeed` 闪烁、自旋。
  - 内置 4 个 `Shape`（PatternA/B/C/D 等）供 JSON 无 nodes 时兜底。

### 4.5 `shooting_stars` 流星（ShootingStarSkyContent）

- **JSON**：`count`、`interval_ticks`、`duration_ticks`、`color`、`seed`。
- **实现**：
  - 构造 N 个 `ShootingStarSpawner`（各带独立随机周期/偏移/生命周期）。
  - 每帧按 `(renderTime + offset) / period` 取模算出当前周期内局部时间，周期内按正弦 `fade = sin(local/lifetime * π)` 决定亮度 → **周期性自动发射**。
  - 渲染：`POSITION_COLOR` QUADS，**加法混合**（`SRC_ALPHA, ONE`），头部亮核 + 12 段渐变拖尾，方向由 spawner 的 yaw/pitch 决定，拖尾固定在世界坐标系（反旋 `skyAngle` 补偿）。

### 4.6 `aurora` 极光（AuroraSkyContent）

- **JSON**：`bands/segments/gradient_steps`、`center_yaw/width/min_pitch/max_pitch`、`wave_amplitude/frequency/speed`、`depth_amplitude/depth_offset`、`ray_strength/edge_softness`、`sphere_radius`、`opacity`、`colors[]`。
- **实现**：
  - 多层"幕帘"（bands 层），每层是 `TRIANGLES` 三角网格：横向 segments × 纵向 gradient_steps。
  - 顶点位置：`pitch = basePitch + 大波sin + 细节波sin*0.34`（多频正弦叠加产生丝带状褶皱）；alpha 沿纵向渐变、横向 `edge_softness` 淡出。
  - `ray_strength` 控制纵向射线感（渐变曲线压缩）；各 band 独立相位，整体 α 随时间慢脉动（`0.58~1.0`）。
  - 反旋 `skyAngle` 固定在世界坐标，`sphere_radius` 可调（默认 100）。

### 4.7 `ribbons` 光带/银河（SkyRibbonContent）

- **JSON**：`segments/gradient_steps`、`center_yaw/base_pitch/spacing/thickness/arc/tilt`、`wave_amplitude/frequency`、`wobble_amplitude`、`speed/edge_softness/blur/opacity/seed`、`colors[]`。
- **实现**：
  - 环状三角网格（`TRIANGLES`），`arc=6.28318` 时为闭环（银河环）；`tilt` 整体倾斜；每帧沿环方向流动（大波+细节波+侧向摆动三频正弦）。
  - 宽度方向 `blur` 高斯式渐隐；颜色沿环向在 `colors[]` 间插值循环。
  - 支持多 Ribbon 实例（`spacing` + 随机 seed 生成 offset/相位/α），可叠出多环银河效果。

### 4.8 `rainbow` 彩虹（RainbowSkyContent）

- **JSON**：`yaw/base_pitch/radius/thickness/segments/arc/opacity/blur`、`colors[]`（默认七色）、时间窗 `time`。
- **实现**：固定位置的半圆弧带状网格，颜色沿弧渐变，`blur` 柔边。通常配合 `time` 条件只在白天显示。

## 5. 生物群系差异化机制（核心卖点）

### 5.1 条件系统（`SkyboxCondition`）

JSON 顶层与每个 layer 支持（`inherit` 机制：layer 未声明则继承顶层）：

| 条件键 | 类型 | 语义 |
|--------|------|------|
| `biomes` | `[ResourceLocation]` | 生物群系 Key 精确匹配（`biomeKey` 相等） |
| `biome_tags` | `[ResourceLocation]` | 群系标签匹配（`biome.is(tag)`） |
| `dimensions` | `[ResourceLocation]` | 维度匹配（`level.dimension()`） |
| `time` | `{from, to}` | 白天时间窗（0~24000，支持跨午夜回卷） |

`hasBiomeFilter = biomes非空 || biomeTags非空`；无过滤 = 全匹配。四者 AND 关系。

### 5.2 权重与切换

- 同一候选键（维度+群系）下，多个 skybox JSON 以 `weight` 竞争；`weight` 最高者胜出。
- 切换有 60 tick 防抖 + 逐 entry 独立透明度淡入淡出（`fade_speed` 默认 0.08）。
- 因此**玩家走进不同群系时，天空在几秒内平滑过渡**——这是 Stellara 的体验核心。

### 5.3 时间窗示例

```json
{ "time": { "from": 13000, "to": 23000 } }   // 仅夜晚活跃
{ "time": { "from": 23000, "to": 13000 } }   // 跨午夜：黄昏+黎明活跃
```

## 6. 1.20.1 Forge → 1.21.1 NeoForge 迁移要点

### 6.1 框架/事件 API

| 1.20.1 Forge | 1.21.1 NeoForge | 说明 |
|-------------|----------------|------|
| `@Mod("stellara")` | `@Mod("pasterdream")`（已有） | 相同 |
| `@EventBusSubscriber(modid, value=Dist.CLIENT, bus=Bus.FORGE)` | `@EventBusSubscriber(modid, value=Dist.CLIENT, bus=Bus.GAME)`（NeoForge 默认 GAME bus） | bus 枚举名不同 |
| `AddReloadListenerEvent`（forge.event） | `net.neoforged.neoforge.event.AddReloadListenerEvent` | 包名迁移 |
| `SimpleJsonResourceReloadListener` | 同名（vanilla） | **完全不变** ✓ |
| `LevelRenderer#renderSky` 签名 | 1.21.1 签名相同：`(PoseStack, Matrix4f, float, Camera, boolean, Runnable)` | Mixin 目标不变 ✓ |
| `VertexBuffer.drawWithShader` ordinal=1 | 1.21.1 中顺序不变（ordinal 0=日月、1=星盘） | Mixin 注入点可平移 ✓ |

### 6.2 渲染 API（mapped 名基本一致）

| 1.20.1（srg→mojmap） | 1.21.1 mojmap | 说明 |
|---------------------|--------------|------|
| `GameRenderer::m_172811_` | `GameRenderer::getPositionColorShader` | ✓ 存在 |
| `GameRenderer::m_172820_` | `GameRenderer::getParticleShader` | ✓ 存在（星空纹理广告牌用它） |
| `DefaultVertexFormat.f_85815_` | `DefaultVertexFormat.POSITION_COLOR` | ✓ |
| `DefaultVertexFormat.f_85819_` | `DefaultVertexFormat.POSITION_TEX_COLOR` | ✓ |
| `buffer.m_166779_` / `m_252986_` / `vertex.m_85950_` / `m_7421_` | `begin` / `addVertex` / `color` / `uv` | 链式 API 相同 |
| `PoseStack.m_85850_()` | `poseStack.last().pose()` | 相同 |
| `Axis.f_252436_` / `f_252529_` | `Axis.XP` / `Axis.YP` | 相同 |
| `Mth.m_14179_/m_14031_/m_14089_/m_14143_/m_14036_/m_14116_` | `Mth.lerp/sin/cos/floor/clamp/sqrt` | 相同 |
| `LegacyRandomSource` | 相同 | ✓ |
| `Minecraft.m_91087_()` | `Minecraft.getInstance()` | 相同 |
| `Level.m_46472_()` / `m_204166_()` | `level.dimension()` / `level.getBiome()` | 相同 |

### 6.3 需要特别处理的差异

1. **Mixin 可用性**：NeoForge 1.21.1 完整支持 Mixin，项目已启用（`pasterdream.mixins.json`，现有 `MinecraftMixin`）→ 新增 `LevelRendererMixin` 无技术障碍。
2. **更优替代（不必须 Mixin）**：NeoForge 的 `RenderLevelStageEvent`（`Stage.AFTER_SKY` / `AFTER_WEATHER`）可直接挂钩天空渲染，本项目 `DyeDreamSkyRenderer` 已用 `AFTER_WEATHER`。但**抑制原版星星仍需 Mixin**（无官方开关）。
3. **`DimensionSpecialEffects`**：1.21.1 构造签名 `(float, boolean, SkyType, boolean, boolean)` 不变；染梦已注册 `SkyType.NORMAL` 特效 → 与 Stellara 的 `hasSupportedSky()` 判定天然兼容。
4. **`getStarBrightness`**（1.21.1 存在）与 `getRainLevel`、`getSunAngle` 均同名可用。

## 7. 染梦维度现状 vs Stellara 能力对照

### 7.1 染梦现状（源自仓库代码调查）

| 模块 | 现状 |
|------|------|
| 维度 | `dyedream_world`：natural + hasSkylight + SkyType.NORMAL（`PDDimensions` + `DimensionAPI`） |
| 群系 | 9 个手写 JSON 群系（`biome_dyedream_0~3`、`deep_ocean`、`mushroom_plains`、`shore`、`river`、`dense_forest`），自定义 `DyedreamBiomeSource` 噪声分配 |
| 雾色 | `DimensionSpecialEffects.getBrightnessDependentFogColor`：9 群系 × 白天/黄昏/夜晚三档插值 |
| 霞光 | `getSunriseColor`：粉色霞光，仅太阳高度 -0.1~0.2 |
| 极光 | `DyeDreamSkyRenderer`（`RenderLevelStageEvent.AFTER_WEATHER`）：7 层弧形色带程序化极光，全维度统一，按太阳高度算透明度 |
| 粒子 | `AuroraGlowParticle` + `DyedreamEnvironmentRenderer` 群系环境粒子 |
| Mixin | 仅 `MinecraftMixin`（BGM），**无天空相关 Mixin** |
| 原版天空 | 未覆写 `renderSky`，星星/日月/云为原版默认 |

### 7.2 能力对照与缺口

| 能力 | Stellara | 染梦现状 | 缺口 |
|------|----------|---------|------|
| 群系差异化天空 | ✅ 条件系统 + 候选切换 | ❌ 仅雾色差异化 | **核心缺口** |
| 自定义星空 | ✅ 纹理星星+聚团 | ❌ 原版星星 | 大缺口 |
| 行星/卫星 | ✅ | ❌ | 大缺口 |
| 星座 | ✅ | ❌ | 大缺口 |
| 流星 | ✅ | ❌ | 大缺口 |
| 极光 | ✅（幕帘网格） | ⚠️ 已有简化版（7 带） | 可增强/替换 |
| 天空色彩 tint | ✅ | ⚠️ 雾色近似 | 可增强 |
| 光带/银河 | ✅ | ❌ | 大缺口 |
| 彩虹 | ✅ | ❌ | 缺口 |
| 时间窗（晨昏差异） | ✅ | ❌ | 缺口 |

> 染梦的设计文档（`docs/archive/specs/dyedream-world-revamp/tasks.md` §4.5）要求"极光仅寒冷群系显示"，当前实现是全维度统一极光——**Stellara 的条件系统恰好能解决这个历史欠账**。

## 8. 移植方案设计建议

### 8.1 总体思路

在 **PasterDreamAPI 模块新增"天空盒 API"**（`api/client/sky/`），主模块实现渲染器与内容，JSON 数据驱动配置，与 Stellara 同构但用 NeoForge 1.21.1 API 重写（符合"精神续作，非代码移植"项目理念）。

### 8.2 渲染挂钩：两条路线

| 路线 | 方案 | 优点 | 缺点 |
|------|------|------|------|
| A（推荐起步） | `RenderLevelStageEvent`（`AFTER_WEATHER`），沿用现有 `DyeDreamSkyRenderer` 模式 | 零 Mixin 风险，现有代码直接扩展 | 无法抑制原版星星（共存）；绘制顺序受阶段限制 |
| B（完整还原） | 新增 `LevelRendererMixin`（Redirect 星星 + Inject RETURN） | 完全替换原版星空，效果最接近 Stellara | 依赖 Mixin 正确性，需处理 1.21.1 签名细节 |

> 建议：先 A 验证内容效果，后按需加 B 抑制原版星星。项目已有 Mixin 基础设施，B 的风险可控。

### 8.3 API 设计草案（放置于 PasterDreamAPI）

```
PasterDreamAPI/.../api/client/sky/
├── SkyboxAPI.java          // 门面（Facade）：SkyboxAPI.createSkybox("id") / register(...)
├── builder/
│   ├── SkyboxBuilder.java  // 维度天空盒 Builder（layers 组合 + 条件）
│   └── SkyContentBuilder.java
├── SkyboxEntry.java        // record(content, condition, fadeSpeed, weight)
├── SkyboxRegistry.java     // 代码注册 + 数据条目合并（静态，同 Stellara）
├── SkyCondition.java       // 函数式接口 + biome/biomeTag/dimension/and/or/time
├── SkyRenderContext.java   // record（level/camera/biome/dayTime/skyAngle/visibility/...）
├── SkyContent.java         // 接口：id()/priority()/targetAlpha()/render()
└── SkyboxDataReloadListener.java  // SimpleJsonResourceReloadListener（数据层）
```

主模块 `PasterDream/.../client/sky/content/` 放 8 个内容实现 + `SkyGeometry/SkyPoint/SkyColor` 数学工具。
注册挂载：主模块 `ClientSetup` 或独立 `SkyboxClientEvents`，通过 `AddReloadListenerEvent` 注册 reload listener。

### 8.4 染梦 9 群系 × 天空主题映射建议

| 染梦群系 | 主题参考 | 建议内容组合 |
|----------|---------|-------------|
| `biome_dyedream_0`（温暖平原） | plains | sky_tint(暖蓝) + star_field(白/淡蓝) + planet_system + **rainbow(白天)** |
| `biome_dyedream_1`（炎热森林） | forest | sky_tint(绿蓝) + star_field(cyan/pale) + ribbons + shooting_stars |
| `biome_dyedream_2`（寒冷冰雪） | frozen | sky_tint(冷蓝) + star_field(blue) + **aurora(强)** + planet_system |
| `biome_dyedream_3`（温暖海洋） | aquatic | sky_tint(深蓝) + star_field(aqua/cyan) + planet_system(ocean) + ribbons |
| `biome_dyedream_deep_ocean`（晶莹深海） | aquatic 强化 | 同上 + 更暗 tint + 更多卫星 |
| `biome_dyedream_mushroom_plains` | mushroom | sky_tint(淡紫) + star_field(pale/purple) + **constellation** |
| `biome_dyedream_shore` / `river` | aquatic 变体 | 海洋色调的轻量版 |
| `biome_dyedream_dense_forest`（密林） | cherry/forest | sky_tint(暖粉) + star_field(pink) + 密集 ribbons |

### 8.5 分阶段实施计划

1. **阶段一（API 骨架）**：`SkyContent/SkyCondition/SkyEntry/SkyRegistry/SkyRenderContext` + `SkyboxAPI` 门面 + JSON reload listener（PasterDreamAPI）。
2. **阶段二（基础内容）**：`sky_tint`、`star_field`（纹理广告牌）、`planet_system`（billboard + 卫星轨道）、`shooting_stars`——覆盖染梦主要缺口。
3. **阶段三（高级内容）**：`aurora`（幕帘网格版，替换/增强现有 `DyeDreamSkyRenderer`）、`ribbons`、`constellation`、`rainbow`。
4. **阶段四（渲染集成）**：路线 A（RenderLevelStageEvent）先跑通 → 评估路线 B（LevelRendererMixin 抑制原版星星）→ 60 tick 防抖候选切换 + 淡入淡出。
5. **阶段五（内容打磨）**：按 8.4 映射为 9 群系各配一套 JSON；纹理资产按项目规范重新制作（沿用"纹理可直接复制、数据需重创建"原则）；修复极光"仅寒冷群系"的历史欠账。

### 8.6 风险与注意

- **Mixin 签名**：1.21.1 `renderSky` 若走路线 B，需用 `@Redirect` 精确匹配第 2 次 `drawWithShader`（ordinal 1），并适配 NeoForge 的 obf/srg 环境。
- **性能**：`star_field count=1200` × 每帧重建 VBO 可接受（原版星盘同规模）；但每内容独立 `begin/draw` 较多，可后续合并批次。
- **多模块**：API 在 PasterDreamAPI，附属模组（MeltDream/Sanity/Spells）可复用同一套 JSON 为自身维度配天空。
- **纹理资产**：Stellara 的星空/行星 PNG 属于"可直接复制"类别，但按项目理念建议重新绘制染梦专属配色纹理。

## 9. 结论

Stellara 是一个**数据驱动 + 条件选择 + 程序化网格渲染**的天空盒框架，其精华在于：
1. 生物群系/维度/时间三轴条件 + 权重候选 + 60 tick 防抖切换 → 平滑的天空氛围过渡；
2. 8 种程序化内容（tint/星空/行星卫星/星座/流星/极光/光带/彩虹）在半径 100 单位球上组合叠加；
3. 全部参数 JSON 化，改配置即可换一套天空，无需重编译。

其架构与 1.21.1 NeoForge 兼容性良好：渲染 API（shader/vertex/BufferBuilder/Mth）映射名基本不变，`SimpleJsonResourceReloadListener` 与 `DimensionSpecialEffects` 均原样可用，唯一技术决策点是"是否引入 `LevelRendererMixin` 抑制原版星星"。染梦维度（`SkyType.NORMAL` + 9 群系 + 现有极光渲染器）与 Stellara 的判定条件天然契合，按 8.4 映射即可获得"群系各异、昼夜分明的染梦星空"，同时可顺带修复"极光应仅限寒冷群系"的设计欠账。

### 关键实现决策

1. **渲染挂载**：`RenderLevelStageEvent.AFTER_SKY`（天空盒渲染后、云之前），与 Stellara 的 `renderSky` RETURN 注入点等价；Mixin 仅用于抑制原版星星。
2. **1.21.1 API 适配**：`Tesselator.begin(...)` + `buffer.buildOrThrow()` + `BufferUploader.drawWithShader(meshData)`；`getPartialTick()` 返回 `DeltaTracker`（需 `.getGameTimeDeltaPartialTick(false)`）。
3. **维度判定**：`hasSupportedSky()` 改为"SkyType 为 NORMAL 或 END 即可"；维度级过滤由 JSON 的 `dimensions` 条件完成（影灯/风之旅途因无匹配条目自然不渲染）。
4. **候选键**：同一 JSON 的多个 layer 共享 `namespace:path` 键（去掉 `/layer_N` 后缀），整套天空盒整体切换。
