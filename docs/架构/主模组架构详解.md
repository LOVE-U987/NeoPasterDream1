# 主模组架构详解

> 本文档描述 PasterDream 主模组的包结构现状：各域职责、注册时序、关键类分布。
> 分工说明：[API 架构详解](API架构详解.md) 讲 API 模块内部；本文讲主模组与附属；[模块边界](模块边界.md) 讲归属决策。

> **本文档是现状速览，不是规范源头。** 本项目采用测试驱动开发：改动的验收标准是
> 编译测试 + VERIFY 套件 + 游戏实测（见第 8 节），而非文档评审。
> 文档与代码不一致时，以代码为准并请更新本文。统计数字截至 2026-09-15。

---

## 1. 模块定位与开发方式

| 项 | 值 |
|---|---|
| mod ID | `pasterdream` |
| 包根 | `com.pasterdream.pasterdreammod` |
| 规模 | 22 个顶层包、813 个类（main sourceSet） |
| 上游依赖 | PasterDreamAPI（独立前置模组，运行时由本模组打包提供） |
| 主要第三方 | GeckoLib（实体/方块/物品渲染）、Curios（饰品）、Player Animator（可选）、JEI（compileOnly）、KubeJS（可选） |
| 职责 | 全部游戏内容：方块/物品/实体/菜单/粒子/渲染/HUD/世界生成/维度/遗迹/事件/命令 |

开发方式上，本模组的演进由测试闭环驱动（第 8 节），文档只记录结构现状。新代码归属先查 [模块边界](模块边界.md)。

## 3. 入口与注册中心域

### 3.1 PasterDreamMod（主类）

构造器时序（实际执行顺序）：

| 阶段 | 动作 |
|------|------|
| 0 | API 层注册：由前置模组 `PasterDreamAPIMod` 完成，本模组**不**调用 `registerAll`（避免双总线注册错误） |
| 1 | 配置注册：`ConfigTracker` 直接注册 Client/Common 两份 TOML（注册阶段禁止读取配置值） |
| 2 | 玩偶 API 注册：`DollAPI` 两个 DeferredRegister + `PDCustomDolls.register()` |
| 3 | 类加载触发：显式引用 `PDBlocks.BLOCKS`、`PDBlockEntities.*`、`PDEntities.ENTITY_TYPES`、`PDEffects.*`、`PDMenus.*`、`PDFluids*` 等静态字段，使条目在注册事件前填充到 API 的 DeferredRegister |
| 4 | 显式注册本模自有注册器：`PDItems.ITEMS`、`PDCreativeTabs.TABS`、`PDArmorMaterials`、`PDPotions`、`PDSounds`、`PDFeatures`、`PDTreeDecorators`、`PDWorldgenRegistries`（ChunkGenerator/BiomeSource）、`PDStructurePlacements`、`PDRecipeTypes` |
| 5 | 结构与装饰：`PDRuinsRegistration.register()`（遗迹）、`TreePlacerAPI.registerAll`（染梦树 Placer）、`ModDecorations`（commonSetup 中） |
| 6 | 玩家数据层：`PDAttributes::addPlayerAttributes`（挂接 PLAYER）、`PDNetwork::registerPayloads`、`PDGameRules.register()`、`PlayerDataEvents` 生命周期监听 |
| 7 | 游戏总线事件：风向/睡眠/灯影进出/裂隙出生点/竞技场/暮影 BGM 状态/工具转换/VFX 命令 |

`commonSetup` 阶段执行三件关键事：`PDRegistrySanityCheck.verify()`（注册人口断言，分区锚点遗漏立即暴露）、`EntityImmunitySetup.setupAllImmunities()`（集中配置伤害免疫）、`EntityTagSetup.setup()`（实体内置标签）。

`gatherData` 阶段挂接两个 DataGen Provider：`PDBlockTagProvider`（server）+ `PDBlockModelProvider`（client）。

### 3.2 registry/（88 类）

根级 45 类按实际用途分四组：

| 组 | 类 |
|----|----|
| 内容注册 | `PDBlocks`、`PDItems`、`PDBlockEntities`、`PDBlockEntitiesFurniture`、`PDEntities`、`PDEffects`、`PDPotions`、`PDParticles`、`PDMenus`、`PDMenusBlueprint`、`PDMenusDreamnotes`、`PDMenusFurniture`、`PDFluids`、`PDFluidsType`、`PDSounds`、`PDAttributes`、`PDArmorMaterials`、`PDCreativeTabs` |
| 世界生成注册 | `PDBiomes`、`PDDimensions`、`PDFeatures`、`PDPlacedFeatures`、`PDRuinsRegistration`、`PDStructurePlacements`、`PDTreeDecorators`、`PDWorldgenRegistries`、`PDLootTables` |
| 数据与规则 | `PDBlockTags`、`PDItemTags`、`PDGameRules`、`PDAdvancements`、`PDTrades`、`PDRecipeTypes`、`PDRegistrySanityCheck`、`PDCustomDolls`、`ModDecorations` 与四个主题装饰类（Dyedream/Ice/LampShadow/Ocean） |
| 事件与运行时 | `PDEntityEvents`、`PDEffectEvents`、`PDArenaEvents`、`PDArenaBossManager`、`LampShadowEvents`、`MeltdreamChestEvents` |

子包：

| 子包 | 类数 | 组织方式 |
|------|-----|---------|
| `registry/blocks/` | 17 | 按主题分区：Boss/ColdDomain/Custom/Dolls/Dungeon/DyedreamPhase2/Functional/Furniture/Materials/Misc/Research/Shadow/Simple/Structure/Vegetation/WindJourney/Workshop |
| `registry/items/` | 14 | 按类型分区：Armor/Blocks/Blueprint/ColdDomain/Curios/Dolls/Dreamnotes/Foods/Functional/Furniture/Materials/Music/SpawnEggs/Tools |
| `registry/creativetabs/` | 12 | 按主题分区：ColdDomain/Curio/Debug/Disc/Dyedream/Entity/Food/Functional/Shadow/Souvenir/Weapon/Wind |

### 3.3 双轨注册的实际行为

主模条目分两条路进入注册表：

1. **API 门面通道**：`PDBlocks`/`PDEntities`/`PDBlockEntities`/`PDMenus`/`PDParticles`/`PDFluids` 等通过 `BlockAPI`/`EntityAPI` 等 API 门面的 Builder 创建，静态字段填充到 API 的 DeferredRegister（已由前置统一挂总线），主模构造器只需显式引用触发类加载。
2. **主模自有通道**：`PDItems.ITEMS`、`PDCreativeTabs.TABS`、`PDSounds`、`PDFeatures` 等主模自己的 DeferredRegister 在构造器中显式 `register(modEventBus)`。

新内容优先走 API 门面（ItemAPI 双轨约定见 [API 架构详解](API架构详解.md) 3.2）。

## 4. 内容域

### block/（145 类）

根级平铺 111 个方块类（染梦植物系、阴影结构系、工坊系、人偶系、竞技场系等），复杂方块独占子包 `block/entity/`（34 个 BlockEntity：炼药锅/梦蓄器/研究台/精铸工坊系列/各类箱筐/人偶/书架等）。无特殊机制的方块不建类，直接在 `registry/blocks/PDBlocksSimple` 等注册类中构造。

### item/（152 类）

根级平铺 149 个物品类（融梦系列 10、暗影系 6、武器系列、蓝图/笔记/调试工具等），子包 `item/armor/` 3 个护甲类。组织惯例与方块一致：系列共享逻辑提取 Helper，独立武器成类。

### entity/（56 类）

| 子包 | 类数 | 内容 |
|------|-----|------|
| 根级 | 3 | `EntityTagEvents`/`EntityTagSetup`（内置标签）、`SpellEffects`（法术效果表——留在主模的内容数据） |
| `entity/mob/` | 33 | 生物实体（暗影系/风系/友善生物/竞技场 BOSS 亚伦柯斯之手等） |
| `entity/projectile/` | 13 | 投射物（法杖弹体系/法术弹/影魔球等） |
| `entity/client/` | 6 | 亚伦柯斯之手的专属 Model/Layer/Renderer |
| `entity/damage/` | 1 | 免疫配置数据 |

### menu/（19 类）

容器与界面菜单：工艺方块类（炼药锅/梦蓄器/研究台/精铸工坊系列/暗影高炉）、容器类（野餐篮/阴影箱/风泊筐/书桌系列/融梦水晶箱/存储袋）、书籍类（梦笔记/无尽追梦者之书/玩家书）、功能类（蓝图/阴影选择/存储袋）。与 `client/screen/` 19 个 Screen 一一对应。

### fluid/（4 类）与 recipe/（1 类）

`fluid/` 两种流体实现（融梦液体/阴影液体）+ `fluid/types/` 两种 FluidType。`recipe/` 仅 `ShadowBlastFurnaceRecipe`（暗影高炉数据包配方类型），其余配方走原版数据包。

## 8. 测试体系（smoketest/，20 类）

本项目以测试驱动演进：**改代码 → `compileJava` → 相关 VERIFY 套件 → `runClient` 实测 → 提交**。`smoketest/` 包是该闭环的自动化落点，分两层：

### 8.1 VERIFY 钩子层（19 个 `*VerifyHooks`）

按功能域划分的验证套件，运行方式：

```powershell
# 在 PowerShell 中显式运行相关套件
$env:PASTERDREAM_VERIFY = '1'
$env:PASTERDREAM_VERIFY_SUITES = 'core,wind-journey'
.\gradlew :PasterDream:runClient
```

默认 `all` 只运行基础集合；主流程等专项套件需显式选择,详见[测试指南](../开发指南/测试指南.md)。

| 钩子（套件） | 验证域 |
|--------------|--------|
| `PDMainFlowVerifyHooks` | 主流程 |
| `PDCurioVerifyHooks` | 饰品/属性 |
| `PDSanityTickVerifyHooks` | 理智 tick |
| `PDSecondDreamVerifyHooks` / `PDDyedreamVerifyHooks` | 第二梦境 / 染梦维度 |
| `PDWindJourneyVerifyHooks` / `PDWindLakeVerifyHooks` | 风之旅途 / 风湖 |
| `PDTwilightLanternVerifyHooks` / `PDShadowIntrudeVerifyHooks` | 暮影提灯 / 暗影入侵 |
| `PDArenaExitVerifyHooks` / `PDEndlessBookVerifyHooks` | 竞技场 / 无尽之书 |
| `PDBlueprintVerifyHooks` / `PDDreamnotesVerifyHooks` | 蓝图 / 梦笔记 |
| `PDEntityGalleryVerifyHooks` / `PDGalleryVerifyHooks` | 实体画廊 |
| `PDStructureVerifyHooks` / `PDPortingVerifyTest` | 结构 / 迁移回归 |
| `PDStaleCommentVerifyHooks` | 陈旧注释扫描 |

断言由 `PDVerify` 提供（`assertAttribute`/`assertEffect`/`assertRegistered` 等行为断言），报告输出到控制台与 `run/pd_verify_report.json`。

### 8.2 端到端冒烟层（PDSmokeTest）

环境变量 `PASTERDREAM_SMOKETEST=1`（或 `-Dpasterdream.smoketest=true`）激活，正常游戏零影响。激活后全自动执行：创建超平坦世界 → 注册表体检 → 发放测试物品 → 打开炼药锅 GUI → 注入液体/填料/触发合成 → 断言产物与消耗 → 关键节点截图至 `run/screenshots/` → 自动退出进程。

### 8.3 边界

VERIFY/smoke hooks 属于「勿上收 API」清单（见 [API 边界](../参考/API边界.md)）——测试钩子始终留在主模，依赖具体内容条目。

## 9. 与 API 的关系

主模 302 个文件引用 API（截至 2026-09-15 取证），高频包：`util`(119)、`entity`(57)、`item`(32)、`worldgen`(31)、`client`(24)、`effect`(20)。

两条约定：

1. **注册走 API 门面优先**：新简单物品/方块优先用 `ItemAPI`/`BlockAPI` Builder，主模自有 DeferredRegister 用于 API 未覆盖的类型（创造模式标签/药水/声音/世界生成注册表）。
2. **上收需判定**：主模「通用基类/工具类」是否上收 API，用 [API 边界](../参考/API边界.md) 的三零判定；玩法数值、具体内容、HUD、VERIFY 钩子一律留主模。
